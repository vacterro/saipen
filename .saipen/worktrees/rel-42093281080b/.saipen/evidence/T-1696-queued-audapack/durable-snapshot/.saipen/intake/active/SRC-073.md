# PERF-004 closure correction — passive inbox freshness budget

## Request

Correct the PERF-004 residual documented in AUDAPACK_20260920_2326.md: the
passive inbox freshness budget expired on every normal active dashboard
repaint.

## Corrective clause

The active dashboard cadence is `MainWindow.BRIDGE_POLL_ACTIVE_MS = 4000`, and
Qt timers fire at or AFTER their requested interval, so a passive freshness
budget of 4.0 s (equal to the cadence) expired on every repaint and the passive
cache performed a physical inbox scan on effectively every active repaint.

Correction: `audapack.agent_inbox._PASSIVE_FRESHNESS_SECONDS` is now 8.0 s, a
documented value that exceeds the active cadence by a meaningful margin and
guarantees at least one normal 4-second repaint is served from zero-I/O passive
state. Expiry still performs exactly one fresh physical probe, and
`validity_inbox_cache()` / `force=True` still probe immediately. The passive
freshness age defaults to `time.monotonic()` rather than wall-clock time, so a
system clock correction can neither expire all passive entries nor extend a
stale verdict; an explicit `now` argument is retained for deterministic tests.

Regression evidence: `tests/test_agent_inbox.py` now contains regressions tied
to the real 4-second cadence (t=1000.0 scan 1, t=1004.1 still scan 1), timer
jitter survival (4.05 / 4.2 / 4.5 s), expiry probe then reuse, a 20-second
active-run call-count measurement (6 repaints produce 3 physical scans), the
same bounded ratio across 100 retained project roots (600 reads produce 300
scans), and a monotonic-vs-wall-clock isolation test.
