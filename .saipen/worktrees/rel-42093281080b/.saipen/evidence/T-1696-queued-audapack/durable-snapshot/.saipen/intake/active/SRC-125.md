PROBLEM

The ChatGPT userscript ZIP dropdown ("Attach project archive")
currently displays all registered AUDAPACK projects instead of
only enabled projects.

The operator expects the dropdown to contain exactly the
projects enabled in AUDAPACK Project Room.

VERIFIED ROOT CAUSE

1. audapack/bridge/server.py, GET /v1/projects,
   approximately lines 883-907:

   The registry response includes every project and exposes
   the "enabled" boolean.

   This is intentional. Do not change this API into an
   enabled-only registry.

2. resources/AUDAPACK_WIDGET.user.js:

   renderManualArchiveMenu(), approximately line 19989.

   The rendering loop at approximately line 20019 iterates
   manualArchiveMenuState.projects without checking
   project.enabled.

   Disabled projects therefore become selectable buttons.

3. The same userscript maintains a registry cache:

   manualArchiveProjectsCache
   dispatchManualArchiveRegistryRequest()
   readManualArchiveRegistry()
   manualArchiveProjectsCacheUsable()
   openManualArchivePicker()
   manualArchiveRefreshProjects()

   Cache TTL: 5 minutes.
   Hard TTL: 30 minutes.

   Cached registry data can preserve the unwanted entries.

4. The backend already rejects disabled projects in
   audapack/bridge/server.py::_archive_project_eligibility().

   This validates the intended archive access policy:
   disabled projects must not be selectable for attachment.

IMPLEMENTATION

A. Add a small reusable enabled-project filter at the
   userscript's manual archive registry/picker boundary.

   Preserve original project IDs, names, and ordering.
   Require enabled === true, not truthiness.

B. Apply the filter consistently to the visible ZIP menu
   across fresh responses, cached responses, stale-result
   handling, Refresh, and reopen.

   Prefer one canonical filter rather than separate
   implementations at each rendering/caching location.

C. Handle a project becoming disabled while its dropdown
   remains open.

   After a successful registry refresh, remove the disabled
   project from visible choices.

   Reject selection if an outdated UI item represents a
   project no longer enabled in the current authoritative
   registry state.

D. Preserve the existing request generation, single-flight,
   deadline, offline fallback and stale-while-revalidate
   mechanisms.

   Do not create additional polling or unbounded requests.

E. Distinguish an empty enabled set from a failed registry
   request.

   If the registry succeeds but no projects are enabled,
   display:

   "No enabled AUDAPACK projects."

   Keep existing offline/error feedback for real failures.

F. Preserve current project ordering, grouping assumptions,
   selection behavior and ZIP attachment workflow.
