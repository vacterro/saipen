SAIHANDOFF — Durable State vs Ephemeral Scratch Contract

ROLE

Continue as the SAIPEN protocol implementation agent.

Implement a protocol-level storage safety contract so agents cannot place durable or sole-copy project state in temporary, cache, scratch, auto-cleaned, or otherwise ephemeral locations.

This is based on a real production loss observed in SAILEARN.

INCIDENT

SAILEARN used:

    V:/_TEMP_/sailearn-home-m7

as its HOME/runtime state location.

That HOME contained valuable state including:

    SAIBUD-1..7 adapters
    model cards
    registry manifests
    training lineage
    evaluation/runtime artifacts

The user's V:/_TEMP_ directory is intentionally auto-cleaned.

During a long-running agent session, that directory was deleted through the Recycle Bin.

Result:

    SAIBUD-1..7 HOME artifacts were lost.
    Only SAIBUD-8 survived elsewhere.

The repository did not delete these files.

The immediate cause was external cleanup.

The protocol defect is that SAIPEN allowed an agent to select an ephemeral path as the sole durable HOME without warning or blocking.

GOAL

Introduce an explicit and enforceable distinction between:

    DURABLE STATE

and:

    EPHEMERAL SCRATCH

Agents must never store important persistent state only in an ephemeral location.

CORE INVARIANT

If loss of a path would require reconstruction, destroy lineage, lose evidence, lose model artifacts, lose registry state, lose user work, or materially alter project history, that path MUST NOT be classified as ephemeral.

Equivalent rule:

    EPHEMERAL means safe to delete at any moment.

If that statement is false, the path is not valid EPHEMERAL storage.

STORAGE CLASSES

Add explicit storage classes.

1. DURABLE

Examples:

    protocol state
    model registry
    model adapters
    model cards
    checkpoints intended to survive the run
    training lineage
    evidence
    accepted artifacts
    user deliverables
    persistent caches whose loss causes meaningful recomputation
    project state
    long-lived runtime state

Requirements:

    persistent location
    explicit ownership
    stable path
    recoverability policy
    must survive process exit
    must survive reboot
    must not live under known temporary roots

2. EPHEMERAL

Examples:

    compiler scratch
    unpack staging
    disposable intermediate files
    transient stdout captures
    temporary patch generation
    temporary conversion outputs
    download staging
    test scratch

Requirements:

    safe to delete at any instant
    must not be the only copy of important data
    must be reproducible or disposable
    must not be referenced as canonical project state

3. CACHE

Optional separate class if useful.

CACHE may be deleted without correctness loss, but reconstruction may be expensive.

It must never contain unique canonical state.

4. EXTERNAL / USER-OWNED

Existing user data outside protocol ownership.

SAIPEN must not relocate or delete it without explicit contract.

DURABLE ROOT

Add a protocol concept such as:

    durable_root

or equivalent canonical configuration.

Projects may resolve durable state under:

    project-local ignored state

or:

    configured machine-wide durable state root

Example conceptual structure:

    SAIPEN_DURABLE_ROOT/
        <project-id>/
            runtime/
            registry/
            models/
            evidence/

Do not hard-code a specific drive.

Allow explicit configuration.

For the current machine, a path such as:

    V:/___VAC/__K/__STATE/

would be an appropriate class of location if configured by the user.

Do not infer that every non-TEMP path is durable.

EPHEMERAL ROOT

Also define:

    scratch_root

The protocol may use OS or user-defined temporary roots for disposable work.

Examples:

    %TEMP%
    %TMP%
    configured scratch folders

The user's environment also contains a custom auto-cleaned root:

    V:/_TEMP_/

SAIPEN must support registering arbitrary user-defined ephemeral roots.

Example conceptual configuration:

    ephemeral_roots:
      - "%TEMP%"
      - "%TMP%"
      - "V:/_TEMP_"

Do not assume only OS-standard TEMP directories are ephemeral.

PATH SAFETY CHECK

Before accepting any path for durable state, SAIPEN must evaluate whether the resolved path is under a known ephemeral root.

Conceptual result:

    classify_path(path) ->

        DURABLE_ALLOWED
        EPHEMERAL_ALLOWED
        DURABLE_FORBIDDEN_EPHEMERAL_ROOT
        UNKNOWN_REQUIRES_EXPLICIT_DECISION

Path comparison must use platform-correct canonical identity.

On Windows account for:

    case-insensitivity
    slash normalization
    environment expansion
    symlink/junction/reparse resolution where practical
    relative path normalization

DURABLE-ON-TEMP BLOCK

If a component declares persistent/durable storage and resolves under an ephemeral root:

    HARD BLOCK

Example:

    component: SAILEARN_HOME
    requested:
        V:/_TEMP_/sailearn-home-m7
    classification:
        EPHEMERAL_ROOT
    requirement:
        DURABLE

Result:

    STORAGE_POLICY_VIOLATION

Message must clearly explain:

    requested path
    matched ephemeral root
    required storage class
    why the path is unsafe
    how to choose/configure a durable root

Do not silently move important data to another location without recording the resolved path.

TEMP USE CONTRACT

Agents may still use temporary directories freely for disposable work.

However, anything written there must satisfy:

    deletion at any time does not damage project correctness

If an artifact created in scratch becomes important:

    promote/copy/move it to DURABLE storage before it becomes canonical.

Example:

    scratch checkpoint
        ->
    accepted checkpoint
        ->
    durable registry artifact

The canonical registry must point only at the durable copy.

SOLE-COPY RULE

Add a general rule:

    No artifact classified as important may have its only authoritative copy under EPHEMERAL storage.

This should cover:

    models
    adapters
    manifests
    reports
    protocol evidence
    training datasets
    generated project artifacts
    runtime databases
    state snapshots

REFERENTIAL INTEGRITY

Protocol state must not persist references to ephemeral artifacts as canonical durable evidence unless explicitly marked transient.

Before a ticket/cycle/model/version becomes complete:

    verify that all required referenced artifacts exist in allowed durable storage.

Example failure:

    model registry entry:
        adapter_path = V:/_TEMP_/foo/adapter

must prevent durable model promotion.

LIFETIME DECLARATION

Where useful, allow tools/projects to declare artifact lifetime:

    RUN
    SESSION
    REBOOT
    PROJECT
    PERMANENT

Map these to storage requirements.

At minimum:

    PROJECT
    PERMANENT

must resolve to DURABLE storage.

RUN
SESSION

may use EPHEMERAL storage.

RECOVERY

When important state is detected under an ephemeral root before deletion:

    warn/block
    provide a bounded migration operation
    verify hashes
    update references atomically
    preserve provenance

Do not simply duplicate and leave canonical references pointing at the old temp path.

POST-LOSS BEHAVIOR

When canonical state is missing:

    detect the loss explicitly

Do not silently treat missing state as a fresh installation.

Classify whether the state is:

    reconstructable
    partially reconstructable
    unrecoverable

For reconstructable state:

    provide deterministic rebuild instructions or operation

For unrecoverable state:

    report exactly what was lost.

SAILEARN REGRESSION FIXTURE

Create a controlled regression based on this incident.

Scenario:

    HOME = <registered ephemeral root>/sailearn-home

Attempt to place:

    model adapter
    model card
    model registry manifest

as durable SAILEARN state.

Expected:

    blocked before canonical state is committed.

Second scenario:

    scratch training checkpoint under ephemeral root

Expected:

    allowed while transient

Then promotion occurs.

Expected:

    candidate must be copied/moved to durable storage before registry promotion succeeds.

Third scenario:

    ephemeral directory disappears mid-run

Expected:

    scratch work may fail/retry
    durable registry and previously promoted models remain intact

CONFIGURATION UX

Provide a discoverable command or configuration surface for:

    show durable root
    set durable root
    show ephemeral roots
    add ephemeral root
    remove ephemeral root
    classify path

Conceptual examples:

    saipen storage status
    saipen storage classify <path>

Exact command names should follow existing SAIPEN conventions.

Do not invent a parallel configuration system if an existing machine/profile configuration mechanism already fits.

PROJECT DECLARATION

Projects should be able to declare named persistent stores.

Example conceptual contract:

    stores:
      SAILEARN_HOME:
        class: durable
      TRAINING_SCRATCH:
        class: ephemeral

SAIPEN should validate resolved paths against the machine storage policy.

FAIL-OPEN / FAIL-CLOSED POLICY

FAIL CLOSED when:

    durable state is about to be placed only in an ephemeral root
    canonical state points to ephemeral storage
    promotion would depend on ephemeral sole-copy artifacts

FAIL OPEN when:

    optional scratch storage is unavailable
    temporary acceleration/cache is missing
    project can safely continue using a durable fallback

Do not hard-block ordinary project execution merely because scratch storage is unavailable.

MIGRATION OF EXISTING PROJECTS

Do not assume only SAILEARN is affected.

Audit SAIPEN-controlled projects for:

    TEMP
    TMP
    _TEMP_
    scratch
    cache
    AppData temp
    OS temporary folders

Only flag cases where the path is used for durable or sole-copy state.

Do not generate noise for legitimate transient use.

TESTS

Add regression coverage for:

1. OS TEMP cannot host durable state.

2. User-configured ephemeral root cannot host durable state.

3. Nested path below ephemeral root is detected.

4. Case/slash variants on Windows do not bypass detection.

5. Relative path resolving inside ephemeral root is detected.

6. Scratch artifact is allowed under ephemeral storage.

7. Scratch artifact cannot become canonical durable state without promotion.

8. Canonical registry cannot reference an ephemeral-only artifact.

9. Deletion of scratch does not corrupt durable state.

10. Durable artifact promotion is atomic.

11. User-defined durable root works.

12. Unknown path classification does not silently become trusted durable state when certainty is required.

13. Existing legitimate temporary workflows remain functional.

14. No protocol action silently commits or relocates unrelated user files.

SAILEARN IMMEDIATE RECOVERY

After the protocol rule exists, use a durable SAILEARN HOME.

Recommended class of path for the current machine:

    V:/___VAC/__K/__STATE/SAILEARN_HOME

provided that this directory is not covered by the user's cleanup automation.

Then:

    rebuild the lost SAIBUD lineage deterministically from repository evidence where possible
    restore registry manifests
    verify hashes/provenance
    preserve SAIBUD-8
    do not fabricate historical artifacts that cannot be reconstructed
    record which artifacts were regenerated versus original

Do not rebuild into V:/_TEMP_.

NON-GOALS

Do not:

    forbid all TEMP usage
    move disposable scratch into permanent storage
    create uncontrolled disk growth
    duplicate every transient artifact forever
    silently assume a random non-TEMP path is safe
    hard-code the user's current drive layout into SAIPEN
    rebuild lost artifacts before a durable HOME is selected
    hide reconstruction behind a clean-looking registry

ACCEPTANCE

This work is complete when:

1. SAIPEN has a first-class durable-vs-ephemeral storage contract.

2. User-defined ephemeral roots are supported.

3. Durable state under a known ephemeral root is blocked.

4. Scratch remains usable.

5. Canonical protocol/project state cannot depend solely on ephemeral artifacts.

6. Projects can declare persistent stores such as SAILEARN_HOME.

7. Missing durable artifacts are detected honestly.

8. A deterministic migration/recovery path exists.

9. Regression tests cover the SAILEARN incident.

10. Existing valid temporary workflows remain operational.

Return:

    storage contract implemented
    configuration surface
    changed files
    regression tests
    full-suite results
    any discovered projects currently storing durable state in ephemeral locations
    migration actions performed
    any remaining manual durable-root decisions
