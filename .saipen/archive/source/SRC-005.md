[P1] [PERF-003] PROVEN BOTTLENECK tools/saipen_engine/test_runner.py::_run_family
EVIDENCE: `_run_family` at test_runner.py:150-160 uses `subprocess.run(..., capture_output=True, text=True, ...)`, causing Python to accumulate the child's complete stdout and stderr before the process exits. Yet the public result immediately calls `_tail(..., limit=8000)` at lines 169-175 and retains only the last 8000 characters from each stream. Synthetic subprocess probes showed parent-side tracemalloc peak allocations of approximately 3.02 MiB for a child emitting 1 MiB, 24.03 MiB for 8 MiB, and 72.05 MiB for 24 MiB, while the returned report still contained only 8000 stdout characters. Thus captured-output memory scales with total emitted bytes, not with the bounded report contract.
ISSUE: A verbose audit/test family can consume arbitrarily large parent memory before `_tail` gets any chance to discard output. A noisy failure, accidental debug loop, or test that emits continuously until timeout can destabilize or OOM the canonical harness itself. This undermines the effectiveness of the timeout/resource boundary exactly when child behavior becomes pathological. W2-004 and W2-005 expose adjacent timeout lifecycle/reporting defects, but even a normally completing child has this independent unbounded-buffer problem.
OPTIMIZE: Drain stdout and stderr continuously into bounded tails instead of `capture_output=True`. A portable implementation may redirect each stream to an owned temporary file and read only its final bounded region after exit/teardown, or use `Popen` with dedicated concurrent drainers/ring buffers whose retained memory is capped. Whichever method is used must fully drain both streams so a child cannot deadlock on a full OS pipe. Integrate the solution with W2-004 process-tree ownership and W2-005 text normalization rather than creating competing subprocess implementations.
GUARDRAIL: Preserve separate stdout/stderr fields, UTF-8 with replacement behavior, PASS/FAIL/TIMEOUT exit semantics and the user-visible tail contract. Do not truncate the actual child pipe without draining it. Timeout handling must still terminate/reap the complete owned process tree, and all returned output must remain JSON-serializable strings. Temporary output files, if chosen, must be deterministically cleaned on PASS, FAIL, TIMEOUT and exceptions.
VERIFY: Run a synthetic family that emits at least 100 MiB on stdout and stderr and exits normally; assert parent peak memory remains bounded near the configured tail/drain buffers and both returned tails are exact. Repeat with a timed-out child that emits continuously and spawns a descendant: verify bounded memory, full process-tree teardown, valid UTF-8-replaced string output and successful JSON serialization.
