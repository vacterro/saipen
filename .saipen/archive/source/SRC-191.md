## Request

SAIPEN

APPEND — ROUTE-BUDGETED PROTOCOL SIZE / REMOVE GLOBAL MARKDOWN SCARCITY

PRIORITY

High.

This append resolves the architectural blocker currently represented by T-1639 and should unblock legitimate protocol evolution such as T-1663.

Do not solve this by merely increasing `human_markdown_total` by another arbitrary constant.

PROBLEM

Current protocol validation enforces a global aggregate human-readable Markdown budget.

Observed current state:

human_markdown_total = 334844 / 334848

Only a few bytes remain.

This aggregate limit is now blocking legitimate protocol evolution even though agents do not load the entire protocol documentation into one context.

The constraint therefore protects the wrong resource.

The scarce runtime resource is not:

"total number of Markdown bytes existing in the repository"

It is:

"how much protocol material a particular execution route actually loads into an agent context."

A global repository-wide Markdown cap has become an architectural anti-feature.

ROOT CAUSE

Protocol documentation grew from a smaller design where aggregate documentation size roughly correlated with model context cost.

That relationship no longer holds.

SAIPEN now has:

- phase-local loading;
- compact indexes;
- targeted KNOWLEDGE retrieval;
- cold-route metadata;
- command-specific authority;
- machine-readable registries;
- selective context loading.

Therefore:

TOTAL_REPOSITORY_DOC_SIZE

is no longer a meaningful proxy for:

RUNTIME_CONTEXT_COST.

The global cap creates false scarcity and encourages harmful behaviour:

- compressing already-clear documentation;
- deleting useful explanations merely to reclaim bytes;
- avoiding explicit safety contracts;
- blocking new machine contracts such as executor capability requirements;
- coupling unrelated protocol modules through one arbitrary shared byte pool.

TARGET

Replace the global `human_markdown_total` admission gate with route-aware protocol load budgets.

The repository may contain more human-readable protocol material as long as no supported execution route exceeds its declared context/load budget.

CORE MODEL

Distinguish at least:

1. repository documentation size;
2. route reachable documentation;
3. mandatory route load;
4. optional/on-demand route load;
5. machine-only metadata.

Only actual route loading should participate in runtime context budget enforcement.

Conceptually:

repository_total
!= runtime_load

A large protocol repository is acceptable if each execution path remains bounded.

ROUTE IDENTITY

Budget according to canonical runtime routes.

At minimum consider routes such as:

- BOOT
- STATUS
- CONTINUE
- SCOUT
- BUILD
- VERIFY
- REVIEW
- SHIP
- WAIT_USER
- RECOVERY
- FUTURE_GATE
- executor admission
- host bootstrap
- response rendering

Exact route taxonomy should derive from existing SAIPEN registries rather than creating an unrelated parallel model.

If several routes share identical loading semantics, they may share a budget class.

Do not create unnecessary per-command duplication.

MEASUREMENT

For each canonical route, mechanically determine the protocol material that the route requires.

Report at minimum:

- mandatory files;
- mandatory byte count;
- optional/on-demand references;
- maximum declared load;
- applicable budget;
- verdict.

Example conceptual output:

route: BUILD
mandatory:
  CORE.md
  EXECUTION.md
  phases/build.md
  selected STYLE contract
mandatory_bytes: 18234
budget_bytes: 48000
verdict: PASS

route: VERIFY
mandatory_bytes: 21402
budget_bytes: 48000
verdict: PASS

Exact values are implementation-owned.

Do not hard-code example numbers.

TRANSITIVE LOADS

Account for actual transitive mandatory references.

If route A always requires B, and B always requires C, the mandatory budget must include A+B+C.

Do not count optional links merely because they exist in prose.

Do not count:
- entire KNOWLEDGE trees;
- arbitrary README links;
- optional deep documentation;
- historical archives;

unless the runtime mechanically loads them for that route.

MACHINE-READABLE AUTHORITY

Prefer existing manifests/registries to infer route dependencies.

If current documentation references are too implicit to measure reliably, add the smallest machine-readable route-load declaration necessary.

Avoid parsing natural-language prose as the primary authority.

The resulting model should be inspectable and testable.

GLOBAL TOTAL

Remove `human_markdown_total` as a blocking acceptance gate.

It may remain as:

- informational telemetry;
- trend metric;
- repository growth statistic.

It must not block protocol evolution merely because unrelated documentation exists elsewhere.

If retained:

human_markdown_total = informational

not:

human_markdown_total = admission authority.

PER-FILE SAFETY

Do not interpret removal of the global cap as permission for enormous individual protocol files.

Retain or introduce reasonable controls against pathological files/routes.

Useful guards may include:

- per-file size warning;
- per-route mandatory load budget;
- maximum bootstrap load;
- duplicate-content detection;
- orphan/unreachable documentation diagnostics.

The target is removal of false aggregate scarcity, not unlimited context dumping.

BOOT FAST PATH

Protect BOOT particularly strongly.

Cold-start / first-turn bootstrap must remain small and deterministic.

Increasing repository documentation must not make:

`/goal cc all`

load substantially more material before the first canonical action.

Measure BOOT separately.

A regression should fail if unrelated documentation growth increases BOOT mandatory load.

PHASE LOCALITY

Preserve phase-local loading.

An agent executing BUILD should not load REVIEW/SHIP documentation unless the current route explicitly needs it.

An agent executing SCOUT should not inherit the whole protocol merely because all Markdown exists under `saipen/`.

Use the existing selective-loading architecture as the optimization boundary.

KNOWLEDGE

KNOWLEDGE remains demand-loaded.

Do not count the entire KNOWLEDGE corpus against every route.

Only:
- the compact index if mandatory;
- explicitly selected relevant cards;

should contribute to the effective route load.

Historical/dormant cards are not automatic context cost.

STYLE

Style authority may contribute to route budget only where it is actually loaded.

Do not require loading multiple translated/historical style documents when one canonical active contract is sufficient.

TRANSLATIONS / BROCHURES / PUBLIC DOCS

Human-facing translations, brochures, guides, README variants and public documentation should normally not consume operational runtime budgets unless a runtime route actually loads them.

Do not force engineering protocol growth to compete for bytes with public documentation.

TESTS

Create red-then-green coverage.

PRE-FIX CONTROL

Demonstrate that adding a tiny valid protocol clause currently fails solely because:

human_markdown_total > global cap

even though no runtime route exceeds its actual context budget.

This should be RED before the repair.

POST-FIX

The same legitimate clause is accepted when every route remains within budget.

ROUTE OVERFLOW CONTROL

Create a real failure:

increase mandatory BUILD or BOOT route content beyond its configured budget.

Expected:

validation FAIL.

The new system must still protect runtime context.

UNRELATED DOC GROWTH CONTROL

Add or enlarge documentation not loaded by operational routes.

Expected:

- repository total increases;
- route loads remain unchanged;
- validation stays PASS.

TRANSITIVE CONTROL

Add a new mandatory route dependency.

Expected:

its bytes are included in route load automatically.

OPTIONAL REFERENCE CONTROL

Add an optional/on-demand reference.

Expected:

it does not inflate mandatory route budget.

BOOT ISOLATION CONTROL

Increase unrelated VERIFY/FUTURE documentation.

Expected:

BOOT mandatory load remains byte-identical.

OBSERVABILITY

Provide a compact diagnostic command/report using the existing validator or appropriate owner.

Conceptually:

protocol load budgets:
  BOOT       12.1K / 32K PASS
  CONTINUE   18.4K / 48K PASS
  SCOUT      25.0K / 64K PASS
  BUILD      27.3K / 64K PASS
  VERIFY     30.2K / 64K PASS
  REVIEW     28.7K / 64K PASS
  SHIP       24.1K / 64K PASS

repository human markdown:
  336K informational

Exact output format and budgets are implementation-owned.

Avoid verbose output by default; respect the new operator readability contract.

T-1639

Resolve T-1639 through this architecture rather than:
- arbitrary manual deletions;
- semantic compression for byte farming;
- another one-time global cap increase.

If investigation proves some truly duplicated/provably obsolete documentation exists, it may still be cleaned, but cleanup is not the primary solution.

T-1663

After the new budgeting model is green, immediately re-evaluate T-1663.

The machine-readable ticket/work capability requirement contract must not remain blocked merely because four aggregate Markdown bytes were unavailable.

Implement the smallest clean `requires` capability declaration necessary for executor admission.

Prefer structured ticket/detail metadata over prose parsing.

A ticket should be able to add requirements such as:

repo_write
process_exec
test_exec
windows_native

without requiring arbitrary protocol-wide documentation trimming.

RELATION TO EXECUTOR ADMISSION

This work is strategically important because T-1651 already provides the internal executor capability admission model.

T-1663 is required to let Work declare additional ticket-specific capabilities.

Removing the obsolete aggregate documentation limit should directly unblock this path.

Do not broaden this append into SAIRoute/ZAICODE consumer wiring if that belongs to T-1664.

First finish the SAIPEN-side authority cleanly.

COMPATIBILITY

Existing validators should continue to detect:
- broken references;
- missing canonical files;
- invalid registries;
- route cycles where prohibited;
- genuinely excessive runtime context;
- duplicated authority where already forbidden.

Only the aggregate global Markdown byte count should lose blocking authority.

MIGRATION

Do not require rewriting all documentation.

Prefer deriving initial route load sets from current canonical registries and existing explicit phase/command relationships.

If a new manifest field is required, migrate current routes once and validate completeness.

Fail closed when a mandatory runtime route has no determinable load contract.

Do not silently treat unknown mandatory dependencies as free.

PERFORMANCE

Route budget validation must remain cheap.

Do not repeatedly parse the entire repository for every command invocation.

Heavy validation belongs in validator/test/update paths.

Runtime routing should consume precomputed or bounded metadata.

NON_GOALS

- unlimited protocol growth;
- removing context discipline;
- loading the whole protocol into models;
- deleting useful docs to save bytes;
- increasing every budget;
- changing lifecycle semantics;
- changing ticket priority;
- implementing T-1664 downstream integration;
- replacing selective KNOWLEDGE loading;
- hiding real context-overflow risks.

ACCEPTANCE

1. `human_markdown_total` no longer blocks otherwise-valid protocol changes.
2. Repository total Markdown may exceed the old 334848-byte threshold.
3. Every canonical operational route has a measurable bounded mandatory load.
4. BOOT remains tightly bounded.
5. A genuine route-budget overflow fails validation.
6. Unrelated documentation growth does not change operational route budgets.
7. Existing protocol integrity checks remain green.
8. T-1663 is unblocked from the obsolete Markdown-cap constraint.
9. Canonical core suite returns red=0 / new_red=0 on the final exact tree.
10. The implementation does not require deleting useful documentation merely to reclaim aggregate bytes.

SUCCESS CRITERION

SAIPEN should optimize the amount of protocol an agent must READ, not artificially minimize the amount of protocol documentation that is allowed to EXIST.

Repository growth is acceptable.

Context growth must remain bounded.
