SAIPENDEFECT — RECOVERY REQUIRES OPERATOR TO MANUALLY MUTATE PROTECTED CANONICAL FILES

Observed workflow:
1. saipen recover correctly detects malformed canonical STATE/BOARD records.
2. It produces an exact deterministic repair.
3. The active agent cannot apply that repair because .saipen/* is protected by
   PROTECTED_CANONICAL_NAMESPACE.
4. The operator is instructed to manually edit STATE.md / BOARD.md.
5. After each manual repair, recover may expose another canonical inconsistency
   and require another manual edit.

This creates an operator-in-the-loop repair loop and defeats autonomous recovery.

Current concrete example:
- malformed STATE transition DONE -> BUILD was detected;
- recover determined the legal repair was DONE -> SCOUT;
- agent was forbidden from applying the bounded STATE.md repair;
- operator manually changed STATE.md;
- next recover then discovered three BOARD repairs:
  - T-1269 DOING ownership has an incomplete/invalid owner + claim_time pair;
  - T-1270 is incorrectly under DOING although not started and should be TODO;
  - T-1268 is under DONE without mandatory verify evidence;
- agent is again forbidden from repairing the canonical namespace.

REQUIRED CONTRACT
The operator must never be required to manually edit raw .saipen Markdown as
part of normal recovery.

Introduce a privileged bounded canonical repair path.

Preferred model:
1. `saipen recover` creates a deterministic repair plan.
2. The plan contains exact before/after canonical mutations.
3. Fast validation runs against the proposed complete state.
4. If operator approval is required, approval authorizes the repair PLAN, not
   manual file editing.
5. A trusted SAIPEN mutation path applies the exact repair atomically.
6. Re-run validation.
7. Roll back automatically if validation fails.
8. Emit one canonical recovery event with evidence.
9. Continue the original ticket automatically.

Agents must still be forbidden from arbitrary direct writes to .saipen/*.
The permitted route should be a dedicated trusted command/API such as:
`saipen recover --apply-approved-repair <repair-id>`
or equivalent. Guard should authorize mutations produced by the trusted SAIPEN
engine while continuing to reject arbitrary agent writes.

Also improve recover so it gathers the full bounded repair set first instead of
forcing: repair one field -> rerun -> discover next field -> ask operator again.

ACCEPTANCE
Given a legacy repository containing all currently observed defects at once:
- malformed phase transition;
- incomplete ownership pair;
- ticket in wrong BOARD section;
- DONE ticket without verify evidence;
one recover operation must:
- detect the complete bounded repair set;
- request at most one operator approval if policy requires approval;
- apply all approved repairs through the trusted engine;
- validate canonical STATE/BOARD/LOG;
- compact if needed;
- resume the original ticket;
without requiring the operator to open or manually edit STATE.md, BOARD.md, or
LOG.md.
