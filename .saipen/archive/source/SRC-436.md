## Request

Перед рефакторингом задавать строгие invariants. Не исправь короткое чтение, а гарантируй полное, согласованное чтение или явный отказ при нарушении условий.

Ввести отдельный adversarial verification этап. Агент обязан самостоятельно попытаться сломать собственное решение до объявления DONE. Отдельный независимый audit остаётся дополнительным контролем.

Ограничить scope каждой волны. Один подсистемный контракт, полный regression suite, benchmark, затем следующая задача. Не смешивать одновременно journal integrity, architecture и release.

Перестать превращать каждый экзотический сценарий в P0 автоматически. Приоритизировать по реальному риску, достижимости и последствиям.

Вернуться к главной цели: производительность и автономность. Не позволять бесконечным исправлениям диагностического JSON поглотить весь инженерный бюджет

SAIPEN должен превращать препятствия в разрешённые действия, а не в обязанности оператора.

Нам нужен не протокол, который идеально объясняет, почему агенту нельзя работать. Нам нужен протокол, который безопасно делает всё возможное, чтобы агент мог работать.

1. Один факт, один authoritative owner. Другие компоненты могут иметь read-only projections, но не независимые версии истины. По-японски 一元管理 (ichigen kanri, единое управление).
2. Простой путь должен оставаться простым. Обычная задача не должна тащить за собой release, crew, multi-account или recovery machinery, если они не нужны.
3. Замораживать новые возможности, а не исправления. Пока критические workflows ненадёжны, никаких новых архитектурных надстроек.
4. Протокол должен завершать собственную бухгалтерию. Если Work законно DONE, все необходимые evidence есть и дополнительные approvals не нужны, source reconciliation должна происходить автоматически. Но никаких автоматических обходов security или operator gates.
