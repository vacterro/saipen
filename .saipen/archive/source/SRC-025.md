[P1] [CORE-001] tools/saipen_engine/release.py::execute_release/_apply_release/_stage_and_commit/_verify_index_after_gate
EVIDENCE:
- execute_release performs `_preflight_plan(root, plan)` before entering `_apply_release` (release.py:1319-1356).
- `_apply_release` acquires `project_writer_lock` only afterwards (release.py:2463-2468); `_apply_release_locked` does not repeat the complete immutable-source preflight under that lock.
- `_stage_and_commit` stages content, runs the ship gate, calls `_verify_index_after_gate`, then executes `git write-tree` (release.py:2858-2885).
- `_verify_index_after_gate` proves changed PATH membership/state, not the blob identity of each release-owned path against the bytes reviewed by the immutable plan (release.py:2784-2842).
- The implementation explicitly anticipates a "hook or concurrent git" changing the selected tree later (release.py:2898-2908), so non-cooperating Git mutation is already inside the intended threat/concurrency model; the project writer lock cannot serialize an external `git add`.
- Deterministic isolated reproduction against the current verifier:
  1. clean repo with tracked `a.txt`;
  2. stage reviewed content `reviewed-A`;
  3. simulate a foreign post-gate restage of the SAME owned path to `UNREVIEWED-B`;
  4. `_verify_index_after_gate(root, plan)` returned `{'ok': True}`;
  5. `git show :a.txt` returned `UNREVIEWED-B`;
  6. `git write-tree` successfully captured that substituted blob.
- Because the changed path remains `a.txt`, the set-based verifier sees no ownership drift. A restage after the ship gate but before `write-tree` therefore makes the new bytes the "intended" tree, and the later committed-tree equality check cannot distinguish them from reviewed bytes.
DEFECT:
The release safety invariant is path-bound but not byte-bound at the final immutable-tree boundary. A concurrent/non-cooperating Git writer can replace the index blob of an allowed release path after validation without changing the path set. If replacement occurs before `write-tree`, the substituted content becomes `intended_tree`; the subsequent HEAD-tree == intended-tree check can pass and publication can proceed with bytes that were never part of the reviewed plan.
REPAIR:
- Bind the immutable release decision to expected content/deletion identity for every release-owned scope path, not merely path membership. Reuse the authoritative reviewed-scope hashes where available and freeze them into an immutable plan manifest; handle reviewed deletions explicitly.
- After `git write-tree`, validate that immutable tree object against the frozen reviewed manifest: each owned path must resolve to exactly the expected blob/content hash or expected deletion. Do not certify by rereading mutable working-tree bytes.
- Refuse before commit/publication on any tree/blob mismatch and restore the owned index according to existing rollback rules.
- Move the final preflight inside `project_writer_lock` as well to close cooperative-writer PLAN/APPLY drift, while retaining the post-`write-tree` byte verification because an external Git process does not honor that lock.
- Prefer committing the already-verified tree deterministically, or retain the existing post-commit tree equality check as an additional defense against index/hooks changing the tree after the immutable-tree verification.
VERIFY:
- Add a deterministic race/red-control hook immediately after the ship gate and before `write-tree`; restage one already-owned path with different bytes. Release must refuse and must not publish.
- Same path with unchanged reviewed bytes must remain valid.
- Cover addition, modification, deletion, crew scope, metadata carriers, and pre-existing foreign staged paths.
- Assert the generated immutable tree's owned blob IDs/content hashes equal the frozen reviewed manifest before any publication.
- Run targeted release tests, full tools unittest discovery, ruff, `validate.py --gate ship`, and the canonical release/audit gate family in a complete Git checkout.

- forges producer-operation ownership over manual/foreign layers;

- makes provenance materially false.
