DEFECT 1 — INVALID next_action CAN ENTER STATE

Current SAIPAL state contained freeform prose similar to:

    operator: python -B tools/saipal.py authority enroll --release-root PATH ...

Strict SAIPEN readers/mutating verbs reject that value because executable next_action grammar accepts only canonical forms such as:

    WAIT: ...
    saipen ...
    RUN: ...
    RESUME: ...
    PHASE <phase> <T-###>

The invalid value therefore causes:

    RECONCILE_REAUTH_REQUIRED

even though the underlying project is not corrupt and is legitimately operator-blocked.

This is a SAIPEN state-contract defect.

A system that validates next_action strictly on read must not casually permit an invalid next_action to be persisted earlier in the lifecycle.

DEFECT 2 — WAIT_OPERATOR IS NOT REGISTERED

SAIPEN emits:

    WAIT_OPERATOR

from the refusal path around entry.py, but WAIT_OPERATOR is absent from the canonical error-code registry.

Observed consequence:

    unregistered_code: true
    detail: "refusal code missing from REGISTRY.json error_codes"

This is internally inconsistent by SAIPEN's own registry contract.
