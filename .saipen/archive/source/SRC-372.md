public GitHub release. Respect any private-public boundary.

Choose the safest supported non-destructive synchronization strategy:

blindly merge unrelated cohorts.

known baseline failures, and execute mandatory publication gates

Reject an unsafe public release even if focused tests pass.

Publish only after the real existing broker authorizes the exact
destination, branch, cohort, operation and relevant source identity.

The operator's general maintenance preference is not a substitute
for a cryptographic broker receipt.

When broker approval is missing, prepare ONE exact approval packet
via a supported host and leave the release ready without repeated
free-form permission questions.

5. VERIFY REAL GITHUB OUTCOME

After a permitted publication, independently read the actual GitHub
target branch from the remote service.

Require the exact intended commit SHA or an explicitly supported,
verified ancestry/merge outcome.

Do not mark GitHub synchronized because an old cohort matches or
because a remote tip merely changed.
