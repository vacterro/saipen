## Request

SAIPEN

SAIHANDOFF — AUTOMATIC TICKET-SCOPED SELF-AUDIT

EXECUTOR: SAIPEN agent
PRIORITY: P2
MODE: Small architectural enhancement
OBJECTIVE: Self-review before legitimate ticket completion

MISSION

Ensure agents automatically inspect their own implementation
for newly introduced defects after successful verification,
without requiring repeated operator reminders.

Reuse the existing REVIEW phase.

Do not introduce a new lifecycle phase, independent
AutoHunt subsystem, persistent queue, or mandatory full
repository scan.

ARCHITECTURAL BASELINE

Relevant existing files:

saipen/phases/review.md
saipen/phases/verify.md
saipen/phases/hunt.md
saipen/MAINTENANCE.md
saipen/CONVERGE.md
saipen/CORE.md

Relevant implementation:

tools/saipen_engine/operations.py

Existing regression neighbors:

tools/test_t1304_review_p0_repair.py
tools/test_verify_oracle.py
tools/test_t1645_zero_hunt.py

The existing REVIEW phase already reruns the ticket's
verifier and inspects oracle integrity.

The missing contract is an explicit, bounded inspection
of the implementation delta for defects not covered by
the original verification.

IMPLEMENTATION

Extend the existing REVIEW procedure with a lightweight
ticket-scoped self-audit.

Trigger only when the current ticket contains an
attributable implementation change.

Execute after successful VERIFY and before SHIP.

Do not execute a new global HUNT.

SELF-AUDIT SCOPE

Inspect:

1. The exact implementation diff owned by the ticket.
2. Modified functions and their direct callers.
3. Changed public contracts and relevant consumers.
4. Error handling and failure paths.
5. Boundary cases, including null, empty and invalid input.
6. Resource lifecycle, cleanup and repeated execution.
7. Concurrency and state consistency where relevant.
8. Whether the tests actually cover the implemented behavior.
9. Whether changed fixtures or assertions conceal defects.
10. Whether the implementation accidentally affects
    unrelated user workflows.

Scope follows the actual implementation delta.

Do not examine unrelated modules without a concrete
dependency or failure signal.

REUSE EXISTING REVIEW

The new inspection supplements existing REVIEW checks.

It does not replace:

- The declared ticket verifier.
- Regression evidence.
- Oracle integrity.
- Source acceptance.
- Security and ownership gates.

Reuse available diff and test evidence.

Do not repeat the full Core suite merely to perform
the self-audit.

Use focused additional tests only for a concrete
uncovered failure hypothesis.

FINDING DISPOSITION

No finding:

Record a concise self-audit result in the existing
REVIEW evidence and proceed normally.

Confirmed P0/P1 defect within the current scope:

Return to BUILD through the canonical lifecycle.
Fix the defect, reverify and review again.

Confirmed lower-priority defect outside the current
ticket's acceptance scope:

Create or link an existing follow-up ticket using
canonical operations.

Deduplicate against all BOARD sections.

A follow-up must never be counted as already fixed.

Unconfirmed suspicion:

Record the exact uncertainty.
Do not manufacture a regression or block successful
Work based solely on speculation.

Do not create tickets merely to demonstrate that
AutoHunt ran.

BOUNDED EXECUTION

Use one focused inspection pass per implementation
revision.

Reuse the existing REVIEW retry budget.

Do not start a second global HUNT.

Do not create recursive review-of-review Work.

Do not trigger a fresh audit merely because a ticket
was closed.

When REVIEW returns to BUILD, the next inspection
covers the new implementation delta.

Verification-only, inherited_verified and no-delta
tickets must not perform a fictional source-code audit.

Documentation-only changes receive an appropriately
scoped documentation consistency check.

SECURITY AND AUTHORITY

Never expand ticket scope automatically.

Never modify another agent's changes without admission.

Never turn a finding into unauthorized implementation.

Never weaken existing acceptance criteria.

Never mark the ticket complete when its actual
required behavior remains broken.

No source mutation after DONE under the old ticket.

No fabricated independent reviewer identity.

The inspection is a self-audit, not independent
human or second-agent approval.

SIMPLICITY REQUIREMENT

First determine whether a small REVIEW contract change
and existing evidence mechanisms are sufficient.

Do not introduce new STATE or BOARD fields.

Do not introduce a new public CLI command.

Do not create a new persistent evidence schema.

Do not add a separate execution agent.

Only propose a machine-enforced extension if a
reproducible negative control demonstrates that
the existing REVIEW contract cannot enforce the
required behavior.

Any additional gate must reuse existing authoritative
evidence and cannot create circular closure dependencies.

REGRESSION

A. Normal code fix:
   Self-audit runs before SHIP.

B. Bug introduced in the implementation:
   Self-audit identifies the actual defect and routes
   through existing BUILD correction semantics.

C. Green but weakened test:
   Existing oracle integrity checks remain effective.

D. No implementation delta:
   No redundant code scan.

E. Existing unrelated defect:
   No accidental scope expansion.

F. Duplicate finding:
   No duplicate ticket.

G. Repeated continuation:
   No repeated audit of unchanged reviewed bytes.

H. Converge:
   Existing full HUNT stages F and I remain unchanged.

I. Foreign owner:
   No unauthorized mutation.

J. Review retry cap:
   Existing bounded refusal behavior remains effective.

PERFORMANCE ACCEPTANCE

Measure incremental REVIEW time on representative:

- Small Python correction.
- Medium multi-file change.
- Verification-only ticket.
- Security-sensitive correction.

Compare against the existing behavior.

The desired result is a small increase in immediate
review effort that avoids expensive future regressions.

Do not claim savings that have not been measured.

Admit this enhancement as separate Work through the
canonical protocol.

If admission is unavailable, prepare the bounded change
without modifying production source.

Do not bypass any authority gate.

SUCCESS CRITERION

Agents automatically inspect their own implementation
before completing a ticket.

A green test suite is no longer treated as sufficient
reason to skip examining the implementation delta.

No additional full HUNT is required per ticket.

The normal workflow remains:

BUILD -> VERIFY -> REVIEW -> SHIP -> DONE

No additional lifecycle phase.

No recursive audit loop.

No manual operator reminder.
