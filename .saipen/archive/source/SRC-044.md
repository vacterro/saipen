======================================================================
A. FIX RECONCILE_REAUTH_REQUIRED SEMANTIC COLLAPSE
======================================================================

Current code defect:

tools/saipen.py continue path effectively does:

    if reconciliation.code == RECONCILE_REAUTH_REQUIRED:
        reauthorize_valve(...)

This is wrong.

RECONCILE_REAUTH_REQUIRED is not synonymous with:

    SAFETY_VALVE_TRIPPED

The same code can represent:

- safety-valve reauthorization;
- blocker operator decision;
- legacy BOARD adoption;
- legacy DONE attestation;
- legacy next_action decision;
- other explicit operator-owned reconciliation states.

Therefore `continue` can currently receive:

    RECONCILE_REAUTH_REQUIRED
    canonical_next_command =
        saipen recover --adopt-legacy ...
        OR
        saipen recover resolve-blocker ...
        OR
        saipen recover resolve-next-action ...
        OR
        saipen recover --attest-legacy-done ...

and incorrectly call:

    reauthorize_valve()

which then answers:

    valve has not tripped; no fresh budget is owed

This exact nonsense was observed live.

FIX:

Do not route on the broad result code.

Route on the actual bounded remediation semantics.

A valve reauthorization may occur automatically through `cc` ONLY when the
reconciliation result explicitly proves:

    reason == SAFETY_VALVE_TRIPPED
    or equivalent canonical structured discriminator.

For every other operator decision:

preserve and emit its exact:

    canonical_next_command
    operator_decision_available
    blocking_surface
    blocking_field
    evidence_reference

Do not approximate it with `cc`.

Required regression:

for EVERY current producer of RECONCILE_REAUTH_REQUIRED:

    continue must either:
    - execute the correct automatic route; or
    - expose the exact operator-owned command;

never route all of them through reauthorize_valve.

======================================================================
B. USER INTENT MUST ENTER BEFORE OLD EXECUTION DEBT
======================================================================

Current protocol already says explicit user intent is durable first:

    saipen user-request <text>

and operations.user_request explicitly documents itself as OUT-OF-BAND.

But the OpenCode guard currently runs Fleet prepare before nearly every
canonical command.

Its local exception set contains roughly:

    recover
    ticket compact
    fleet preflight/scan

It does NOT make `user-request` a reliable ingress.

Therefore old project debt can prevent the operation whose purpose is to
persist the NEW user's request.

That contradicts the user-request contract.

Required invariant:

    explicit new user instruction
    -> durable intake receipt FIRST

even when unrelated execution/recovery state is blocked.

The task may later be unable to RUN if it truly depends on an unresolved
operator decision.

But the instruction itself must not disappear and must not require the human
to manually discover an intake command.

Test:

project contains unrelated RECONCILE_REAUTH_REQUIRED condition

operator submits a new explicit task

expected:

    request body persisted
    user_explicit Work projected when safe
    exact route returned

NOT:

    Fleet blocks before intake exists

Do not weaken canonical-state integrity to achieve this.

Separate:

    INGRESS authority

from:

    EXECUTION authority.

D. SEAT IS AUTOMATIC
======================================================================

The live SAIFREN agent asked:

    "give me a role"
    "how do I become main"

This is wrong for ordinary entry.

BOOT already states:

- SAIPEN_AGENT is optional;
- without it, a valid project inherits STATE.agent;
- host identity is not a seat.

Enforce this mechanically in the entry path.

Normal task start must NEVER ask the operator to invent a seat name.

Decision order:

1. explicit trusted launcher actor, if supplied;
2. legal inherited STATE.agent;
3. canonical platform/default seat derivation for a genuinely unseated project;
4. only a real ownership contradiction requires operator intervention.

User prose such as:

    "бери seat"
    "начинай"
    "ты главный исполнитель"

is authorization to proceed under the existing canonical ownership rules.

It is NOT a request for the user to invent protocol metadata.

E. COMMAND CLASSES MUST HAVE ONE OWNER
======================================================================

The OpenCode plugin currently owns a local hard-coded concept:

    isCanonicalRecoveryOrInspection

This is already drifting from engine semantics.

Replace the growing exception list with ONE canonical command-effect
classification owned by SAIPEN.

At minimum classes equivalent to:

    DIAGNOSTIC
    INGRESS
    RECOVERY
    EXECUTION

Examples:

DIAGNOSTIC:
    status
    validate
    --help
    fleet preflight/scan

These must never trigger mutating Fleet recovery merely to be READ.

INGRESS:
    user-request
    start

These must be reachable so explicit user intent can be persisted.

RECOVERY:
    recover
    exact ticket compact
    other registered canonical repair operations

These must remain reachable under the debt they repair.

EXECUTION:
    claim
    transition
    checkpoint
    ordinary continue
    etc.

These go through ordinary execution admission.

The plugin consumes this classification.

Do not duplicate the verb taxonomy in JS and Python.
