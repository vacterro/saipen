3. FIRST: CONTRACT AND FEASIBILITY SPIKE

Determine whether terminal crew closure can be represented using existing canonical epoch identity plus independently derived deferred scope, without inventing a ticket.

Prove the minimal legal path on a disposable fixture before making broad changes.

Required distinction:

A. Published terminal release.
B. Local no-publish terminal completion.
C. Refused or incomplete terminal convergence.

These outcomes must never be interchangeable.

If the current architecture cannot safely represent B, implement an explicit terminal outcome contract rather than bypassing A.

Document schema and recovery compatibility before changing stored evidence.

4. VERSIONLESS NO-PUBLISH

Do not require a VERSION file for an authorized local no-publish completion unless a version is independently required by the operation's actual semantics.

Move or scope release-version validation appropriately.

Preserve strict version validation for real publication.

Never synthesize version "0", use a fake release tag, or claim an artifact was published when no publication occurred.

Do not change Wintage package.json, userscript versions, CHANGELOG, Git HEAD, or source fingerprint as a workaround.

5. TICKETLESS CREW EPOCH

Resolve the producer/consumer contradiction:

- A valid epoch can have no ticket_id.
- Terminal planning currently unconditionally requires ticket_id.

Prefer canonical crew epoch identity and verified deferred-scope receipts as the terminal ownership basis when the workflow does not genuinely have a single ticket.

Do not invent a ticket, borrow T-246 from an older epoch, or mutate a committed historical carrier to make validation pass.

If no legitimate deferred scope exists, refuse clearly.

If ownership is ambiguous, refuse clearly.

Protect multi-ticket deferred scope, project lineage, exact file hashes, review bindings, and epoch identity.

6. POST-SHIP TRUTH

Make the release verdict and its immutable evidence identify the actual terminal outcome.

Do not infer whether publication happened from historical STATE.mode.

The post-ship validator must distinguish:

- No-publish with a valid terminal receipt.
- Real publish with its commit/tag/remote evidence.
- Missing or forged receipt.
- Stale source identity.
- Wrong epoch.
- Incomplete convergence.

Keep read-only capability restrictions and current-session authority enforcement.

An authorized no-publish closure performs zero Git mutations and zero remote operations.

A real publication must retain all existing Git, source, scope, version, and remote gates.

Do not globally skip SC-11.
