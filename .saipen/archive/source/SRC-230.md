PHASE 1 — NEW TASK ADMISSION AND OWNERSHIP

Priority: P1

Problem:

Target:
Make the distinction between captured user intent and authorized execution unambiguous and machine-readable.

Required behavior:

A. A new actionable user request must route through START before CONTINUE or unrelated operational probes.

B. START must distinguish:
- request recorded
- work claimed
- existing work resumed
- queued pending work
- blocked by conflicting ownership
- recovery required

Use the repository's existing canonical codes wherever available. Do not introduce redundant status enums.

C. USER_REQUEST_RECORDED must not be represented as WORK_CLAIMED.

D. If an unrelated active ticket prevents the new task from being claimed, return its ownership boundary and one exact canonical next action.

E. Preserve captured user intent without silently transferring ownership.

F. Do not close, overwrite, or reassign the active ticket merely to make the new mission executable.

G. Preserve the existing recoverable/degraded operation policy. Do not turn temporary host limitations into unconditional hard blocks.

H. Ensure /goal cc all and ordinary autonomous continuation retain their legitimate semantics. This mission must not introduce new arbitrary ticket-count or human-confirmation interruptions.

I. An executor must not treat model-authored reasoning or prose as an ownership receipt.

Regression scenarios:
- New task with no active ticket.
- New task while the same work is active.
- New unrelated task while another ticket is in VERIFY.
- Request successfully captured but not claimed.
- Missing or unavailable host admission proof.
- True ownership conflict.
- Resume after recovery.
- Repeated START using the same receipt.
- Direct CONTINUE without a new user task.
- Conflicting agent identity or seat.
