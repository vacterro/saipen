# SAIPEN ↔ SAIPATCH Run to Closure Contract v1

## Ownership

SAIPEN owns semantic truth:
- whether useful autonomous work remains;
- whether the project is genuinely complete;
- whether continuation requires a human/external event;
- whether current convergence is valid for the latest audit generation.

SAIPATCH owns transport automation:
- observing the authoritative OpenCode completed/idle boundary;
- querying SAIPEN's machine status;
- enqueueing exactly one synthetic `cc` only when told to continue;
- stopping on completion or any unsafe boundary.

Neither side duplicates the other's logic.

## Required machine surface

SAIPATCH consumes only:

```text
saipen status --json
```

The command must be read-only and expose:

```json
{
  "automation": {
    "schema_version": 1,
    "disposition": "CONTINUE | COMPLETE | WAIT_USER | WAIT_EXTERNAL | BLOCKED | INVALID",
    "next_command": "cc | null",
    "reason_code": "stable_machine_code",
    "reason": "human-readable explanation",
    "audit_quiescent": true,
    "audit_epoch": "deterministic-digest",
    "convergence_current": true,
    "closure_complete": true,
    "source_fingerprint": "deterministic-digest",
    "completed_at": "timestamp-or-null"
  }
}
```

Rules:
- `next_command == "cc"` only for `CONTINUE`.
- For every other disposition, `next_command == null`.
- Unknown schema/version/disposition fails closed.
- Assistant prose is never machine authority.
- `SAIPEN_CLOSURE_COMPLETE` may be printed for humans, but SAIPATCH must never parse it as truth.

## Terminal behavior

```text
CONTINUE      -> enqueue exactly one synthetic cc
COMPLETE      -> stop; enqueue nothing
WAIT_USER     -> stop/pause; enqueue nothing
WAIT_EXTERNAL -> stop/pause; enqueue nothing
BLOCKED       -> stop/pause; enqueue nothing
INVALID       -> hard stop; enqueue nothing
```

## Closure rule

`COMPLETE` is valid only when all of the following are mechanically true:

1. Audit transport is canonically quiescent.
2. No actionable audit-linked work remains.
3. One full current convergence pass completed after the latest audit-empty boundary.
4. That convergence is bound to the current `audit_epoch`.
5. No new audit generation arrived afterward.
6. No qualifying source mutation invalidated convergence.
7. No workable TODO/DOING/follow-up remains.
8. No human/external/blocking boundary remains.

A physically empty `audit/` directory is not sufficient.

## Race rule

If a new audit generation arrives while post-empty convergence is running or after it completed:

- the old closure attempt is invalid;
- the new audit must be consumed;
- a new post-empty convergence is required;
- `COMPLETE` cannot refer to the older epoch.

## Safety rule

Run to Closure may pre-authorize repeated ordinary `cc` continuation across soft SAIPEN safety-valve boundaries only.

It never pre-authorizes:
- first publish;
- destructive confirmation;
- manual verification;
- secrets/input owned by the user;
- policy/product decisions owned by the user.

## Transport rule

At most one RTC-generated `cc` may be queued or in-flight per OpenCode session.

Duplicate completion events must not duplicate sends.
