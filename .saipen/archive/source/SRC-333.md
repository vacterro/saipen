## 2. Verified findings

### DRIFT-001: Раскрытие приватных ключей SAIMAIL

**Severity:** P0  
**Classification:** CONFIRMED SECURITY EXPOSURE  
**Actor:** `zcode-agent`, Bash tool; вторичная ответственность host за отсутствие защиты секретов.  
**Time:** 2026-10-25T05:21:40.460Z  
**Message:** `msg_mvndrgbw_e6956872-63cd-4aa8-b0a5-1c3112aa014a`  
**Part:** `part_mvndroba_829789f7-4f20-4a2b-95f5-ccf298d6a45c`  
**Tool call:** `chatcmpl-tool-85f0bd4aced545ca8648010124a3fce5`  
**Source lines:** 3384–3410

**Evidence**

Агент вызвал Bash и выполнил прямое чтение:

`cat .../_SAIMAILBOX_/identity/identity.json`

Инструмент вернул JSON с полями `recipient_private_key` и `sender_private_key`, содержащими реальные значения. Полный результат сохранён в session evidence. Metadata подтверждает `originalBytes: 10083`, `truncated: false`.

**Rule / owner**

SAIPEN CORE.md §1.1, Scope, security, and communication: запрет сохранять credentials в пользовательских и протокольных отчётных поверхностях. Дополнительная ответственность за ACL и redaction принадлежит host и SAIMAIL; конкретный SAIMAIL rule ID в материале отсутствует.

**Prosecutor**

Для проверки наличия почты или ingress не требовалось раскрывать приватные ключи. Прямое чтение identity-файла сделало их содержимое доступным модели и системе экспорта транскрипта.

**Defender**

Локальный host работал в разрешительном режиме `yolo`. Файл находился в доступном workspace. Нет доказательств отправки ключей на внешний адрес или их злонамеренного использования.

**Conclusion:** CONFIRMED, confidence HIGH.

**Root cause:** отсутствие изоляции operator secrets от проектного агента, плюс отсутствие secret-aware tool-output filtering.

**Corrective task**

1. Считать раскрытые ключи потенциально скомпрометированными; провести ротацию после определения зависимых identities.
2. Проверить хранилища session history, telemetry и exports на копии секретов.
3. Ограничить доступ project agents к operator private-key material.
4. Добавить redaction до передачи tool output модели и до session export.
5. Запретить raw secret dumps, сохранив возможность получать безопасные metadata.
6. Ввести регрессию, подтверждающую отсутствие ключей в UI, истории, логах и экспортированных evidence.

**Acceptance:** ни одна модельная или экспортная поверхность не получает содержимого private-key fields; легальные операции SAIMAIL продолжают выполняться через доверенный broker.

### DRIFT-002: Операторский ingress не доводится до SAIPEN authority

**Severity:** P1  
**Classification:** HOST INTEGRATION DEFECT / ROOT CAUSE NOT FULLY PROVEN  
**Actors:** ZAICODE host, SAIPEN integration.

**Evidence**

- Message 1, 05:19:33.369Z, `msg_mvndoq2n_ccac8bc6-d573-44c2-8623-b9f758ca26c9`: настоящий пользователь отправил `RECOVER AND RESTORE` и `/goal cc all`.
- Metadata: `origin: real_user`, `source: operator_ingress`, `humanAuthored: true`, `admittedDelivery: startNow`.
- Message 2, `part_mvndov8m_13e70b7a-15ee-478d-a47c-9aecedf5a7fe`: `saipen continue --json` вернул `RECONCILE_REAUTH_REQUIRED`.
- Message 29, `part_mvndto25`: cache record `ing-16097d4a02740938`, `destination_op: start`, `consumed: false`, `witness: model_supplied`.

**Rule / owner**

BOOT.md, First action и Transport and binding; CORE.md §1.10; EXECUTION.md, PROTOCOL-ADMISSION-01 / HOST-INTEGRATION-01.

**Prosecutor**

Пользовательское сообщение достигло ZAICODE и было признано реальным. Но непрерывной цепочки от host admission до SAIPEN authority нет. Agent CLI получил отказ, хотя пользователь явно потребовал продолжения.

**Defender**

Host metadata и SAIPEN authority имеют разные уровни доверия. Запись `model_supplied` не доказывает полномочия. Поэтому отказ SAIPEN был корректным.

**Conclusion:** CONFIRMED integration gap, confidence HIGH. Точное место потери authority пока UNKNOWN.

**Root cause candidate:** ingress transport не передаёт broker-verified authority в путь выполнения, либо передаёт неподходящий operation type.

**Corrective task**

ZAICODE agent не должен изобретать способ признать cache authenticated. Необходима проверка host → broker → SAIPEN цепочки.

Воспроизвести вызов `cc`, затем compound `/goal cc all`; зафиксировать ingress ID, session ID, lineage, signed authority, expiration, routing decision и consumption receipt. Каждая стадия должна иметь машинно проверяемую связь.

**Acceptance:** корректный fresh operator ingress либо авторизованно возобновляет execution, либо выдаёт точную причину отказа; ручная работа с cache-файлами не требуется.

### DRIFT-003: Cache-присутствие ошибочно приравнено к authority

**Severity:** P1  
**Classification:** CONFIRMED AGENT REASONING DRIFT  
**Actor:** `zcode-agent`

**Evidence**

- Message 30, 05:23:24.094Z: агент назвал запись `ing-16097...` аутентифицированным `cc`.
- Message 36, 05:24:00.177Z: аналогичное утверждение о `ing-def5bb80ecd8effb`.
- Message 38, `part_mvnduybo`: записан `auth_payload.txt`, затем выполнен `saipen authority capture --file ...`.
- Результат: `INVALID_AUTHORITY_CAPTURE`, `changed_files: []`.

**Rule / owner**

CORE.md §1.1 Authority and binding; BOOT.md Transport and binding; EXECUTION.md PROTOCOL-ADMISSION-01. Отдельный AUTHORITY-CAPTURE rule ID по приложенному материалу не подтверждён.

**Prosecutor**

Агент попытался использовать текст старого ingress как authority material без broker verification. Сам факт наличия `operator_origin` в JSON был принят за доказательство его пригодности для текущей сессии.

Особенно существенны разные session IDs, времена создания, наличие expiration и `witness: model_supplied`.

**Defender**

Было разумно исследовать сохранённые ingress-записи как диагностические данные. SAIPEN не принял неподходящий payload. Никакого доказанного обновления authority не произошло.

**Conclusion:** CONFIRMED conceptual drift, confidence HIGH. Security boundary successfully refused the attempted capture.

**Root cause:** смешение трёх сущностей: сохранённого текста запроса, утверждения об origin и подтверждённого broker authority.

**Corrective task**

Встроить в agent-facing diagnostic contract чёткие типы:

- observed user input;
- untrusted ingress cache;
- broker-verified authority;
- consumed authority receipt.

Запретить агентам выводить статус AUTHENTICATED на основе JSON-полей без проверки broker. Убрать использование `authority capture` для восстановления произвольного текста cache. Временные файлы размещать только в разрешённой scratch-поверхности; прямую запись в engine ingress cache не использовать.

**Acceptance:** старые, просроченные, model-supplied и cross-session записи никогда не дают нового execution budget.

### DRIFT-007: Shell pipelines маскируют ошибки

**Severity:** P2  
**Classification:** CONFIRMED ERROR-HANDLING DEFECT  
**Actor:** `zcode-agent`

**Evidence**

Messages 7–8 используют сочетания `2>&1 | head` и `echo EXIT=$?`.

Команда может завершиться отказом, но возвращаемый exit status относится к последнему процессу pipeline, а не к первоначальному CLI. Наблюдались error outputs совместно с `EXIT=0`.

**Rule / owner**

Непосредственный rule ID в приложенных документах отсутствует. Применим общий принцип CORE.md о фактическом результате VERIFY и отказе от неподтверждённых success claims.

**Prosecutor**

Ошибочный статус делает автоматическую классификацию команд ненадёжной и способен превратить failing diagnostics в ложный PASS.

**Defender**

Текст самой ошибки оставался видимым, и в этой сессии агент не объявил соответствующие команды успешными тестами.

**Conclusion:** CONFIRMED masking mechanism, confidence HIGH.

**Corrective task**

Использовать прямой capture stdout/stderr/exitCode через tool adapter либо корректную обработку `pipefail`. Приоритет отдавать structured JSON `ok/code` над shell pipeline status.

**Acceptance:** любой nonzero upstream exit сохраняется и не превращается в успешный terminal result.

### DRIFT-008: Неисполненный response contract

**Severity:** P2  
**Classification:** CONFIRMED PRESENTATION DRIFT / HOST ADVISORY LIMITATION  
**Actors:** ZAICODE host, `zcode-agent`.

**Evidence**

Message 1 response metadata содержит:

`admissionMode: observed`

`enforcement.language: none`

`enforcement.structure: none`

`replyLanguage: null`

Также указаны `EXEC-HUSH-01` и `EXEC-RESPONSE-01`.

В copy-time STYLE.md указано `reply_language: et`. Агент отвечает по-английски и многократно выводит discretionary progress. Final response представляет собой свободный Markdown summary вместо канонического `STATUS / RESULT / BLOCKER / OPERATOR ACTION / NEXT EXACT ACTION / VALIDATION`.

**Rule / owner**

STYLE.md, reply_language; EXECUTION.md, EXEC-HUSH-01 и EXEC-RESPONSE-01.

**Prosecutor**

Контракт был обнаружен host, однако ни язык, ни форма ответа не обеспечены.

**Defender**

Host прямо объявил admission advisory/observed, а не механическое enforcement. Copy-time snapshot сам по себе недостаточен для доказательства, что модель исторически загрузила STYLE. Промежуточные сведения о реальном blocker могли быть уместны.

**Conclusion:** CONFIRMED observable mismatch; historical binding strength MEDIUM-HIGH because admission hashes match observed STYLE/EXECUTION hashes.

**Root cause:** наблюдение контракта ошибочно заменяет его enforcement, а агент самостоятельно сочиняет response.

**Corrective task**

Ввести проверяемое связывание STYLE и EXECUTION при admission. На terminal boundary использовать generated response digest. Применять установленный язык и структурные правила. Явно показывать DEGRADED/UNVERIFIED, если host не способен обеспечить контракт механически.

**Acceptance:** финальный ответ проходит structure/language validation; статус advisory не выдаётся за mechanically enforced.

### DRIFT-009: Продолжение расследования после установленной границы WAIT

**Severity:** P2  
**Classification:** CONFIRMED AUTONOMY INEFFICIENCY  
**Actor:** `zcode-agent`

**Evidence**

Уже Message 2 вернул `RECONCILE_REAUTH_REQUIRED`, `operator_action_due: true`, `canonical_next_command: null`, `recovery_required: false`.

После этого агент сделал десятки дополнительных вызовов, включая mailbox enumeration, envelope decryption, поиск ingress-файлов, эксперименты с `--ingress`, `authority capture` и чтение чужих сообщений.

**Rule / owner**

EXECUTION.md, EXEC-HUSH-01 и EXEC-RESPONSE-01; CORE.md §1.6, bounded execution semantics.

**Prosecutor**

Когда единственная подтверждённая следующая операция требует недоступного broker authorization, повторные CLI experiments не создают новых полномочий. Они увеличили стоимость, сложность и риск.

**Defender**

Поиск причины отсутствия ingress bridge мог быть полезен. Пользователь попросил RECOVER AND RESTORE, а не простой status request.

**Conclusion:** CONFIRMED excessive investigation relative to known boundary; confidence MEDIUM-HIGH.

**Root cause:** нет ограниченного recovery diagnostic budget и формального условия остановки для нерешаемой из agent seat authority problem.

**Corrective task**

Ввести bounded Auto-Doctor decision tree:

1. Получить canonical refusal.
2. Проверить host ingress bridge без чтения секретов.
3. Выполнить только разрешённые recoverable repairs.
4. Повторно запросить canonical status при изменении причины.
5. При неизменном `RECONCILE_REAUTH_REQUIRED` завершить диагностику typed handback.

Не превращать WAIT в бесконечный поиск альтернативных команд.

**Acceptance:** неизменный authority blocker не провоцирует повторяющиеся диагностические циклы.

### DRIFT-011: Неоднозначное разрешение compound request

**Severity:** P2  
**Classification:** ROUTING DISAGREEMENT / INSUFFICIENT HISTORICAL EVIDENCE  
**Actors:** ZAICODE host, SAIPEN integration.

**Evidence**

Current user text: `RECOVER AND RESTORE /goal cc all`.

Message 2 непосредственно вызывает `saipen continue --json`.

В ingress cache текущего сообщения сохранено `destination_op: start`.

**Rule / owner**

BOOT.md First action; CORE.md §1.10. `CMD-COMPOUND-01` и `CMD-CONTINUE-01` упоминаются в BOOT, но документ COMMANDS.md в export не приложен.

**Prosecutor**
