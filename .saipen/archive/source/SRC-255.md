IMPLEMENTATION

STAGE 1 — ARCHITECTURAL CONTRACT

Separate three concepts:

A. IMPLEMENTATION_COMPLETE
The requested internal implementation exists and has passed its applicable verification.

B. ACCEPTANCE_COMPLETE
Every original required acceptance criterion is satisfied by trustworthy evidence.

C. EXTERNAL_GATE_PENDING
Remaining completion depends on operator approval, independent human review, real infrastructure, or another explicitly external authority.

These states must not silently collapse into one DONE verdict.

Retain compatibility with legitimate no-publish SHIP completion. Publishing must not be implicitly required when the ticket only requests local implementation.

STAGE 2 — PREMISE INVALIDATION

Strengthen finding_invalidated without interpreting arbitrary LOG prose as authority.

Investigate a machine-verifiable closure contract with:

- Original requirement and acceptance-clause identity.
- Structured invalidation reason.
- Typed evidence linked to the actual failed premise.
- Provenance and current-state validation.
- Explicit accounting for every remaining acceptance obligation.

A same-ticket E-### reference alone is insufficient evidence of premise invalidation.

If a requirement is still valid but blocked externally, finding_invalidated is not the correct disposition.

If only part of a ticket is fulfilled, require an authorized scope split or durable continuation with explicit lineage.

Never silently redefine the original verify field.

STAGE 3 — CLOSURE ENFORCEMENT

Apply the shared invariant through the canonical ticket finishing path and its validator.

Required properties:

- One authoritative implementation of the rule.
- Zero-write refusal before invalid closure.
- Atomicity of BOARD, LOG, STATE and associated receipts.
- Idempotent retry.
- No alternate completion path bypasses enforcement.
- No unauthorized operator decisions.
- No fabricated evidence or reviewer identities.
- No conversion of a real blocker into a fictional PASS.

Use an explicit refusal code and actionable diagnostics.

STAGE 4 — CONVERGENCE TRUTH

Update the continuation/convergence reporting where necessary.

Distinguish:

- No remaining internally actionable tasks.

- Publication prohibited.

An authorized cc or cc all should autonomously perform available canonical recovery and reconciliation, but must never override genuine admission or operator gates.
