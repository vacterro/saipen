## 1. Incident Analysis and Reproduction

### 1.1 The Measured Failure
During execution of the 29-test combined suite (`tools.test_t1967_qualification_provenance`, `tools.test_t1968_foreign_protocol_route`, `tools.test_t1969_finding_revision_identity`), test `tools/test_t1968_foreign_protocol_route.py::NegativeControlTests.test_a_real_typo_keeps_the_ordinary_refusal` failed once:
- **Expected:** `code == 2`, `payload["code"] == "VALIDATION_FAILED"`, detail `"unknown command: bogusxyz"`.
- **Observed:** `code == 2`, `payload["code"] == "RUNTIME_DRIFT"`.
- **Subsequent isolated runs:** Immediately returned `VALIDATION_FAILED` (PASS).
- **Repeated 29-test combined run:** 29 of 29 tests PASSED in 6.32s.

## 2. Root Cause Investigation

### 2.1 The Origin of RUNTIME_DRIFT
In `tools/saipen.py:400` (`_runtime_drift_payload`):
```python
def _runtime_drift_payload(project_root: Path, command: str) -> dict | None:
    state_path = _state_path(project_root)
    if not state_path.is_file():
        return None
    ...
    match = re.search(r"^saipen_home:\s*\"?([^\"\r\n]+?)\"?\s*$", head, re.MULTILINE | re.IGNORECASE)
    if not match:
        return None
    other_raw = match.group(1).strip()
    mine = HOME.resolve()
    other = Path(other_raw)
    with suppress(OSError):
        other = other.resolve()
    if _same_install_path(other, mine):
        return None
    return {
        "ok": False,
        "code": "RUNTIME_DRIFT",
        ...
    }
```
When an unknown command (`bogusxyz`) is received, the CLI checks whether the target project's `.saipen/STATE.md` declares a `saipen_home` that differs from the executing runtime (`HOME.resolve()`). If they differ, the CLI deliberately diagnoses `RUNTIME_DRIFT` instead of reporting a bare `unknown command`.

### 2.2 Mechanism of the Transient Discrepancy
Three concrete factors explain why `_same_install_path(other, mine)` temporarily evaluated to `False` during the first combined suite run:

1. **Source Extraction / ZIP Working Directory Discrepancy:**
   - In the operator-provided ZIP snapshot, `.saipen/STATE.md` contained `saipen_home: "V:/___VAC/__K/__CODE/_AI_STUFF_AGENTIC/_SAIPEN"`.
   - When extracted into an alternate evaluation or temporary location (e.g. `V:/_TEMP_/...`), `mine = HOME.resolve()` points to the extracted path while `STATE.md` retains the previous path.
   - Any unknown command executed against the un-rebound project triggers `RUNTIME_DRIFT` until `saipen rebind-home` or project-root resolution aligns them.

2. **Subprocess Environment Isolation Gap in `run_cli`:**
   - `test_t1968_foreign_protocol_route.py` defines `run_cli` using `subprocess.run([sys.executable, "-B", str(ENGINE), *argv], cwd=str(cwd or REPO))`.
   - Unlike the hardened fixtures in `test_t1662_repository_interlock.py` or `paths.unbound_environment()`, `run_cli` inherited the ambient process `os.environ` without sanitizing `SAIPEN_PROJECT_ROOT`, `SAIPEN_SKILL_ROOT`, or `PWD`.
   - If an earlier test in the test runner process set or left `SAIPEN_PROJECT_ROOT` pointing to a temporary test fixture with a synthetic or mismatched `saipen_home`, the child CLI bound to that directory and correctly diagnosed `RUNTIME_DRIFT`.

3. **Path String Comparison Edge Cases on Windows:**
   - `_same_install_path` handles case-folding and backslash normalization, but if `other.resolve()` encounters an `OSError` (e.g. file lock, ephemeral mount, or permissions), `other` remains unresolved.
   - Any difference in trailing slashes or 8.3 short names (e.g. `VAC~1` vs `___VAC`) between `other` and `mine` causes string equality to fail.

---

## 3. Classification and Verdict

- **Classification:** **TEST_HARNESS_ISOLATION_ANOMALY** (Environmental sensitivity in subprocess test helper `run_cli`).
- **Production Status:** **NOT A PRODUCTION BUG**.
  - In production, when `saipen` runs inside a project whose `saipen_home` matches its installation, `bogusxyz` returns `VALIDATION_FAILED` (exit 2).
  - When driven with an old runtime against a new project, emitting `RUNTIME_DRIFT` is the **intended, required protocol behavior** (T-1159 / CORE § 1.10).
- **Remediation:**
  - In test harnesses invoking `subprocess.run(ENGINE, ...)`, sanitize `env` using `saipen_engine.paths.unbound_environment()` or explicitly pass `--project-root` to avoid inheriting ambient project binding variables.
