Transport-file absence is treated as sufficient proof

  File absent != Source CLOSED
  File absent != Work DONE
  File absent != binding DELETED

IMPACT:

generation whose Source remains ACTIVE.

This violates the audit cleanup lifecycle contract.

   A. Previously settled DELETED binding.
   B. Missing file whose binding is not yet settled.

2. Case A must remain idempotent.

3. Case B must verify the authoritative receipt status
   before returning cleanup permission.

4. Require:

   - Valid binding identity.
   - Receipt integrity.
   - Source CLOSED or verified retired tombstone.
   - Linked Work DONE.
   - Consistent generation identity.

   unreadable or unresolved.

6. Preserve the existing journaled cleanup path when
   the source is genuinely terminal.

7. Recheck closure conditions under the mutation's
   protected execution boundary.

8. Do not reconstruct or silently relabel Source authority
   from the presence or absence of a file.

  - Missing file + ACTIVE Source => REFUSED.
  - Missing file + unfinished Work => REFUSED.
  - Missing file + corrupt Source => REFUSED.
  - Missing file + CLOSED Source + DONE Work => allowed.
  - Repeated cleanup of already DELETED binding => idempotent.
  - Changed generation bytes => no cleanup of new bytes.
  - Crash before binding settlement => recoverable.
  - Crash after committed deletion => idempotently settled.
