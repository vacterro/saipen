[P2] [W2-004] tools/saipen_engine/commands.py::parse_compound_command
EVIDENCE: parse_compound_command tracks quoted state by toggling `in_quote` on every `"` character. It neither recognizes escaped quote characters nor produces an error for end-of-input with an open quote. Boundary probes showed normal `gg "A + B" + cc` producing two intended segments, but `gg "A \"quoted + text\" B" + cc` was split into `['gg "A \\"quoted', 'text\\" B"', 'cc']`, so the ` + ` inside the logical quoted payload became an executable compound delimiter. A dangling quote probe `gg "unterminated + cc` returned one segment containing the remainder, causing the recognizable later `cc` text to be swallowed into the goal payload instead of the malformed compound input being rejected. The parser exposes only a segment list, so downstream resolution has no lexical-error state with which to fail closed.
DEFECT: Compound routing uses an incomplete quote-state scanner at the execution boundary. Certain malformed or escaped-quote payloads can change command segmentation, while an unclosed quote can silently consume later command-looking text. This violates repeatable dispatch semantics: the same visible ` + ` token changes from data to command boundary based on quote characters that the parser itself does not correctly validate.
REPAIR: Replace the quote toggle with one lexical pass that has explicit quote/escape state and a structured malformed-input result. Support escaped quotes inside a quoted payload if that syntax is part of the CLI grammar; otherwise reject them explicitly rather than accidentally using them to flip state. Detect EOF with an open quote and refuse the entire compound command before any segment is dispatched. Keep quoted ` + ` and quoted newlines opaque, and preserve the current behavior for ordinary unquoted compound separators.
VERIFY: Add parser and routing tests for plain `A + B` payloads, correctly quoted plus signs, quoted newlines, escaped quotes adjacent to ` + `, backslashes before quotes, empty quoted payloads, and dangling quotes. Malformed lexical input must produce one deterministic refusal and execute zero segments. Valid quoted compound input must produce exactly the intended segments, and every recognized command outside quotes must retain an explicit terminal disposition.

[P1] [PERF-001] PROVEN BOTTLENECK tools/saipen_engine/log.py::read_history_snapshot_and_logs_digest
EVIDENCE: The function explicitly claims that each history segment is opened exactly once (log.py:271-280), then first reads every validated path with `p.read_bytes()` at log.py:302-305. After the snapshot has been built it defines `_read_sealed(candidate) -> Path(candidate).read_bytes()` at log.py:347-350 and passes that to `hash_tree_dependency(logs_dir, read_file=_read_sealed)` at log.py:352. `hash_tree_dependency` / `_hash_delete_tree` therefore walks `.saipen/logs` again and reopens every sealed segment. A disposable fixture containing two sealed segments plus active LOG produced exact read counts `LOG-0001.md: 2`, `LOG-0002.md: 2`, `LOG.md: 1`. This is not merely duplicated I/O: the first history snapshot and second sealed-tree digest can observe different generations if a sealed member/content changes between traversals, yet the later digest becomes the APPLY read precondition while PLAN semantics came from the earlier snapshot.
ISSUE: Every mutation PLAN pays two content passes over sealed history, and the supposedly unified snapshot/digest pair is not actually one-generation evidence. Cost scales with total sealed history bytes, while the between-pass race can bind PLAN semantics derived from generation A to a dependency digest from generation B.
OPTIMIZE: Compute both HistorySnapshot and the exact `saipen-delete-tree-v1` `.saipen/logs` dependency digest from one validated traversal and the same witnessed bytes/membership. Do not implement this as “read once, then os.walk/read again through a callback”; either accumulate the sealed digest framing during the authoritative history traversal or retain only the minimal per-segment witnessed bytes/metadata needed to finish that digest without a second filesystem generation. Active LOG remains part of the history snapshot but not the sealed-tree digest, matching the existing contracts.
GUARDRAIL: Preserve exact digest compatibility with `hash_tree_dependency(.saipen/logs)`, ownership/reparse refusal, numeric segment ordering, active LOG encoding checks, illegal-line detection, max_ticket_id derivation and APPLY's fresh under-lock precondition recheck. A membership/content race during capture must fail stale/unstable rather than synthesize a mixed-generation pair.
VERIFY: Instrument a fixture with N sealed segments and require exactly one content read per sealed segment plus one active LOG read. Assert the new logs digest byte-for-byte equals the existing `hash_tree_dependency` result on stable fixtures. Inject replacement, addition, removal and same-size content swap around segment capture and require explicit stale/refusal, never a snapshot/digest pair from different generations. Re-run operation planning, recovery and history hostile-regressions.

[P1] [PERF-002] PROVEN BOTTLENECK tools/saipen_engine/producer.py::ProducerPackage.from_dict / StagingGeneration.scan_ready

GUARDRAIL: Do not skip validation of stale/non-current packages; corrupt READY evidence must remain visible and must still make health invalid where the existing contract requires it. Preserve package_identity, dependency_fp, filename binding, read/write-set validation, source/role currentness and integration semantics. Do not add a weaker “metadata only means valid” path.
