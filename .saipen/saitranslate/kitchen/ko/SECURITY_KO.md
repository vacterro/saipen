# 보안 정책

## 범위

SAIPEN은 사양(specification)과 함께 소수의 로컬 설치/내보내기 스크립트(`bootstrap/inject.ps1`/`.sh`, `uninstall.ps1`/`.sh`, `export.ps1`/`.sh`)의 집합입니다. 서버를 실행하지 않으며, 원격 분석(telemetry)을 수집하지 않고, 어떠한 데이터도 외부로 전송하지 않습니다. 스크립트가 수행하는 모든 작업은 사용자가 이미 제어하고 있는 파일(자신의 `~/.claude`, `~/.gemini`, 프로젝트 `.saipen/` 등)에 대한 로컬 파일 시스템 쓰기 작업뿐입니다.

여기에는 두 가지 다른 수준의 주의가 필요하며, 포괄적인 안전을 주장하기보다 정확히 설명할 가치가 있습니다:

- **사용자 자신의 설정 파일**(`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.aider.conf.yml`)은 구분된 `SAIPEN:BEGIN`/`END` 블록을 추가하거나 제거하는 방식으로만 편집되며, 최초 수정 전에 원본이 `<file>.bak`으로 복사됩니다. 제거 시에는 추가로 `<file>.uninstalled.bak`을 기록한 후 스트리핑합니다.
- **인젝터가 생성하는 스킬 디렉터리**(`~/.claude/skills/saipen` 등)는 SAIPEN 소유의 복사본이며 **백업되지 않습니다**. 설치는 일괄 덮어쓰기를 수행하고 제거는 재귀적으로 삭제합니다. 이는 의도적인 것입니다 -- 이 디렉터리들은 이 저장소 자체 파일의 복사본만 보유합니다 -- 그러나 로컬 스킬 복사본을 직접 수정한 경우, 해당 수정 사항은 다음 `inject`/`uninstall` 시 손실됩니다. 사용자 정의는 복사된 스킬 폴더 내부가 아니라 자신의 설정 블록 또는 포크에 유지하세요.

실제로 보안 보고가 가치 있는 두 가지 경우는 다음과 같습니다:
1. 부트스트랩 스크립트가 주석이나 README에 명시된 범위를 넘어 파일 시스템이나 git 히스토리에 무언가를 수행하는 경우.
2. 프로토콜 자체의 비밀 정보 관리 규칙(RFC.md § 1.1 -- API 키, 토큰, 비밀번호를 `STATE.md`/`BOARD.md`/`LOG.md`/`KNOWLEDGE/`/`kitchen/`/`extensions/`/`saitranslate/kitchen/`/`recovery/`/`logs/`에 절대 쓰지 말 것)에 실제 구멍이 있어, SAIPEN을 따르는 에이전트가 비밀 정보를 커밋되는 파일에 유출하게 되는 경우. 마지막 두 개는 미묘한 것입니다: 리커버리는 손상된 `STATE.md`를 그대로 `.saipen/recovery/`에 복사하고, LOG 실링은 내용을 그대로 `.saipen/logs/`로 이동시키므로, 원본에 도달한 모든 것은 내용을 변경하지 않는 것이 유일한 역할인 메커니즘에 의해 보관됩니다.

## 지원 버전

`main` 브랜치의 최신 태그된 릴리스만 지원됩니다. 이것은 프로토콜 사양이며 수명이 긴 서비스가 아닙니다 -- LTS 브랜치는 없습니다.

## 취약점 보고

GitHub 이슈를 열어주세요. 보고서가 실제이고 현재 악용 가능한 문제(가상이 아님)를 포함하는 경우, 수정 사항이 배포되기 전에 공개적으로 노출되지 않도록 공개 이슈 대신 이 저장소의 **Security** 탭("Report a vulnerability")을 통해 비공개/보안 권고로 표시해주세요.

다음을 포함하세요: 어떤 스크립트 또는 RFC 규칙인지, 구체적인 시나리오, 그리고 (올바른 동작과 비교하여) 실제로 발생하는 일. 다른 버그 보고서와 동일한 증거 기준이 적용됩니다(`CONTRIBUTING.md` 참고).
