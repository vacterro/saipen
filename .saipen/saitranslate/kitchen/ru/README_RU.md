# SAIPEN

**Протокол продолжения для агентов искусственного интеллекта.**Память проекта хранится в обычном
файлах Markdown внутри проекта(`.saipen/`), поэтому любой совместимый холодный агент —
без истории чата, без сессионной памяти — может запускать`/saipen continue`, читать
сохранённые`next_action`, и возобновлять работу без необходимости просить пользователя объяснять заново
ничто. Состояние принадлежит проекту, а не памяти одного поставщика моделей.

**Один командный запрос для возобновления. Состояние в обычных файлах. Проверенные контракты машиной.**

Репозиторий проверяет себя при каждом push; установка, состояние, проверки и
от uninstall — всё локальное — никакой облачной службы, никакого демона, никакой базы данных.

## Что остается

Живая память проекта хранится в`.saipen/`— обычные файлы, которые вы можете читать, сравнивать и
создавать коммит рядом с кодом. Холодный агент отвечает на пять вопросов из файлов
самостоятельно:

|Файл / поле|Ответы|
|---|---|
| `STATE.md` |Что происходит прямо сейчас?(фаза, активный тикет, режим работы, блокировщик) |
| `BOARD.md` |Какая работа существует / какая активна?(граф тикетов: DOING, TODO, DONE, BLOCKED) |
| `LOG.md` |Почему проект достиг этого состояния?(только добавляющий события граф) |
| `KNOWLEDGE/` |Какие устойчивые факты проекта должны выживать в сессиях?|
| `next_action` (в`STATE.md`) |Какое точное действие должен выполнить следующий агент?|

Это контрольный договор, а не предложение по дизайну:`saipen stop`и каждый
переход тикета записывает файлы в фиксированном порядке, и результат проверяется
валидатором. Ничто не хранится в хостированной базе данных, и ничего не теряется когда
сессия завершена.

## Быстрый старт

**1. Установите один раз на каждую машину**— обучает Claude Code, Codex, Gemini, OpenCode,
Aider, Antigravity и любой общий`~/.agents/skills`читатель(FreeBuff и т.д.):

```bash
git clone https://github.com/vacterro/saipen
cd saipen
powershell -ExecutionPolicy Bypass -File .\bootstrap\inject.ps1     # Windows
bash bootstrap/inject.sh                                            # macOS / Linux
```

<sub>What that touches, so nothing is a surprise: it appends a marked
`<!-- SAIPEN:BEGIN -->...<!-- SAIPEN:END -->`блок в инструкцию агента
файлы, которые у вас уже есть(`~/.claude/CLAUDE.md`, `~/.config/opencode/AGENTS.md`,
`~/.codex/AGENTS.md`, `~/.gemini/GEMINI.md`)— создавая резервную копию каждого из них в`.bak`первым делом —
и копирует протокол в соответствующие папки навыков. Ничего за пределами этих
пути, без демона, без сетевых вызовов.</sub>

**2. Начать проект**— откройте агента в своей папке, введите:

> `saipen set`

**Без установки?**Вставьте одну строку в любой агент:

> Прочтите&lt;clone&gt;/saipen/BOOT.md сначала(ядро холодного запуска), затем&lt;clone&gt;/saipen/INDEX.md +&lt;клонировать&gt;/saipen/STYLE.md и следуйте им.

**Изменили мнение?**Одна команда возвращает его:

```bash
powershell -ExecutionPolicy Bypass -File .\bootstrap\uninstall.ps1  # Windows
bash bootstrap/uninstall.sh                                         # macOS / Linux
```

Она удаляет только отмеченный блок(оставляя остальную часть вашего файла без изменений), сохраняет
a `.uninstalled.bak`сделайте копию сначала, а затем удалите папки с навыками.

## Почему бы не использовать историю чата?

SAIPEN направлена на конкретную проблему: ИИ-агент для кодирования, который ничего не запоминает
после окончания сессии. Другие инструменты и привычки частично решают эту проблему:

|Подход|Для чего оно годится|Что оно не несёт|
|---|---|---|
|История чата / память модели|Удобно, без настроек|Зависит от сессии и поставщика; не хранится вместе с проектом, поэтому холодный агент никогда его не увидит|
|Статический`AGENTS.md`/ файл инструкций|Прочие правила и соглашения|Сам по себе не представляет текущее состояние задачи,`next_action`, или историю восстановления|
|Отслеживатель проблем / TODO|Управление задачами и бэклогом|Не определяет сам по себе семантику продолжения агента — что холодный агент должен прочитать и выполнить при возобновлении|
| **SAIPEN** |Живое состояние выполнения, очередь задач, история событий, устойчивое знание и проверяемые правилами продолжения — в обычных файлах рядом с кодом|Ничего; эта комбинация — это контракт|

Разница не в каком-то одном файле. Это в том, что SAIPEN выполняет шаг возобновления
проверяемо машиной: первое действие холодного агента после`/saipen continue`это
определяется сохранённым`next_action`и проверяется валидатором, а не
восстанавливается из памяти.

## Инженерные доказательства

SAIPEN сочетает нормативный обычный файловый протокол с исполняемым, ориентированным на сбой
проверки. Репозиторий демонстрирует проектирование протокола/машинного состояния, Python
инструменты, схема-определяемое состояние, рассуждения о восстановлении, регрессионное тестирование,
границы рабочих процессов с несколькими агентами, и дисциплина спецификации.

- **Проект контракта.** [SPEC.md](SPEC.md)определяет модель продолжения с поддержкой файлов
и стабильный контракт на диске;[CORE.md](saipen/CORE.md)
и[MAINTENANCE.md](saipen/MAINTENANCE.md)описывают текущее нормативное поведение.
- **Проверяемое машиной состояние.**Канонический stdlib-only
  [валидатор](tools/validate.py)читает живой
  [СХЕМА состояния](extensions/schemas/state.schema.json)и проверяет переходы фазы
зависимости билетов, ссылки на граф событий, междокументные
инварианты, возможности и состояние восстановления.
- **Покрытие отказов.** [CONFORMANCE.md](saipen/CONFORMANCE.md)сопоставляет
требования с[сценарными фикстурами](tests/scenarios/); the
  [сценарий-запускатель](tools/run_scenarios.py)выполняет проверки прохождения/провала структуры
включая поврежденное состояние восстановления, недопустимые переходы, циклы зависимостей и
ограничения только для чтения.
- **Контроль регрессии.** [audit_checks.py](tools/audit_checks.py)изменяет
известные хорошие копии и доказывает, что проверки валидатора всё ещё могут выдать красный результат, а не
рассматривать постоянно зеленую проверку как доказательство.
- **Исполняемый уровень.** [saipen.py](tools/saipen.py)обеспечивает журналирование состояния
операции;[bootstrap/](bootstrap/)хранит установку, удаление и экспорт
вспомогательные средства с необязательным[установщиком предварительного хука](tools/install_hook.py).
- **Явные компромиссы.**Основное протокольное состояние — это обычные файлы без запуска
зависимости. Каноническая проверка и инструменты командной строки требуют Python, но используют только
его стандартную библиотеку и не требуют`pip`установки.

## Архитектура

Три уровня, строго односторонние зависимости:

```text
CORE            continuation / state / checkpoint / validation       required
  └─ MAINTENANCE   autonomous HUNT / ADD / CLEAN evolution           optional, on top of Core
       └─ GOAL MODE / SUBAGENTS   opt-in throughput/execution        optional
```

Ядро не зависит от Обслуживания: с отключенным автономным развитием, SAIPEN
все еще является полным протоколом продолжения — холодный агент все еще возобновляется.

- **Состояние машины ядра** — `INIT → PLAN → SCOUT → BUILD → VERIFY → REVIEW → SHIP → DONE | BLOCKED`.
- **Автономное обслуживание**— плата остановлена(ничего работоспособного в`## TODO`,
ничего в`## DOING`)и не`BLOCKED`? Автоматические переходы`HUNT` (сканировать баги)
  → `ADD` (развивать функции) → `HUNT`, без вопросов. Сессия, сидя на
  `BLOCKED`никогда не автоматически охотится
  ([Обслуживание § 2.1](saipen/MAINTENANCE.md#21-autonomous-transitions)).
- **Режим цели** — `/saipen goal <objective>`поворачивает доску и запускает
цель вперёд через ПРОВЕРИТЬ/ПЕРЕСМОТРЕТЬ, попадая в автономное обслуживание
до тех пор, пока не сработает правило завершения или не достигнет лимита выполнения(3 волны / 20 тикетов,
затем проверочные точки и отчет) ([Обслуживание § 2.4](saipen/MAINTENANCE.md#24-goal-mode-autonomous-execution)).
- **Упрочнение**— пакетный ввод разбивается на хирургические тикеты по одному
  (CORE § 1.8); продолжение загрязнённого дерева сохраняет незавершённую работу(CORE § 1.5);
значения, похожие на секреты, удаляются из журналов(`sk-***`) (CORE § 1.2).

| `/saipen status` |Только для чтения: фаза, задачи, блокирующие факторы, устаревание|
| `/saipen stop` |Создать контрольную точку и остановиться|

## Что SAIPEN не является

- **LLM или моделью**— это протокол, который агенты следуют, а не интеллект.
- **IDE или базой данных с хостингом**— состояние представляет собой обычные файлы в вашем проекте;
ничего не хостится.
- **Альтернатива Git**— Git всё ещё владеет историей версий; зафиксируйте
  `.saipen/`как любой другой код.
- **Распределённое согласование**— см. границу параллелизма ниже.
- **Гарантия того, что LLM будет принимать правильные инженерные решения**— оно
уменьшает потерю контекста и дрейф поведения; оно не делает стохастических агентов
непогрешимыми.

Задача SAIPEN — это продолжение/контракт состояния плюс проверка и инструменты —
Передав следующему агенту проверенную машиной начальную точку, а не магию.

**Граница параллелизма.**Журналированные изменения состояния(SAIOPS)использовать
операционную блокировку, ограниченную проектом, и журнал восстановления([OPS § 5](saipen/OPS.md#5-locks)).
Обычные редактирования проекта и отсоединенные авторы находятся вне этой блокировки. SAIPEN
не является распределенным консенсусом, поэтому отсоединенные авторы требуют внешней
координации([SPEC](SPEC.md#concurrency--distribution-boundaries)).

## Примечания по настройке

**Язык ответа.**Агент отвечает на**эстонском**по умолчанию — это настройка, а не требование протокола, и ничего другого в SAIPEN не является эстонским.
Протокол, код, коммиты и каждый документ остаются на английском языке при каждом
значении. Измените это в одном месте: в строке
вверху`reply_language:`эстонском,
[`saipen/STYLE.md`](saipen/STYLE.md). `et`английском,`en`русском,`ru`выбирается из сообщения, которое вы отправили.
`auto`Адаптеры.

****Платформа не охвачена инъектором(DeepSeek, Qwen, standalone
OpenAI и др.)? Замечания по платформам находятся в`extensions/adapters/`.
