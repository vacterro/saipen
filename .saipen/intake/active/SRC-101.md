AUDITED RED CONTROL

    retry_not_before: 2026-09-20T21:00:00Z

and a time after that instant, the supplied implementation returns:

    ACTIVE                       -> DUE_OPERATOR_ACTION
    HELD                         -> DUE_OPERATOR_ACTION
    FUTURE_GATE                  -> DUE_OPERATOR_ACTION
    PERMANENT_WARNING_OWNER      -> DUE_OPERATOR_ACTION
    WAIT_USER_CONFIRMATION       -> DUE_OPERATOR_ACTION
    WAIT_USER_DECISION           -> DUE_OPERATOR_ACTION
    WAIT_ROLE:saitest            -> DUE_OPERATOR_ACTION
    BLOCKED_EXTERNAL             -> DUE_OPERATOR_ACTION

The following are definitely invalid operator-due projections:

    ACTIVE
    HELD
    FUTURE_GATE
    PERMANENT_WARNING_OWNER
    WAIT_ROLE:<role>

WAIT_ROLE is crew/role-owned Work, not a human operator action.
ACTIVE is a generic active blocker.
HELD is used for protocol/backlog holds.
FUTURE_GATE is not inherently a human action.
PERMANENT_WARNING_OWNER is not a timed operator action.
Do not solve this by weakening blocker_class() globally.
That helper has other protocol responsibilities.
Create one dedicated policy owner for deferred-operator eligibility.
For example conceptually:

    deferred_operator_class(blocker)

or an equivalent explicit predicate.
Do not duplicate classification literals across router/status/writer/tests.
