# User request

priority: P1
verify: the requested change is present and demonstrated against the user own description of it

## Request

SAIPEN

P1 — DURABLE EVIDENCE-SURFACE CONTRACT / AUDAPACK FALSE-COMPLETE FIX

CONTEXT

A Problip closure-envelope repair temporarily added `.saipen/evidence/` to the
project evidence contract and successfully produced an archive containing:

.saipen/evidence/PERF-001_WINDOWS_EVIDENCE.md

with source/archive SHA256:

7856719211E999FA47B0C8D21B3F6615BE12AFE0E73D4E4DDDD97D5242C14C9C

However a later SAIPEN lifecycle regenerated `.saipen/MANIFEST.json` and the
evidence/ declaration disappeared again.

Current Problip archive:

_PROBLIP_16.09.26-T21-29-29.zip

proves the regression.

CURRENT OBSERVED STATE

Current `.saipen/MANIFEST.json` conditional evidence directories are:

- logs
- intake
- archive/source
- KNOWLEDGE
- audit

It does NOT contain:

- evidence

Current AUDAPACK result reports:

evidence_files_collected = 142
evidence_files_in_archive = 142
required_evidence_omitted = false

Yet the current ZIP does NOT contain:

.saipen/evidence/PERF-001_WINDOWS_EVIDENCE.md

LOG E-70/E-73/E-74 records that an earlier local repair temporarily declared
evidence/, collected it, and produced a ZIP containing the file.

Therefore the local project manifest edit was not durable.

ROOT CAUSE TO PROVE

Find the canonical source that regenerates `.saipen/MANIFEST.json`.

The durable SAIPEN protocol definition/template must recognize:

.saipen/evidence/**

as an authoritative closure-evidence surface.

Do not fix this by repeatedly editing generated project MANIFEST.json files.

TARGET A — CANONICAL CONTRACT

Add `evidence/` to the canonical SAIPEN evidence manifest/template/generator.

Required behavior:

- newly initialized projects declare evidence/
- existing project manifests refreshed by SAIPEN retain/add evidence/
- later lifecycle/reconcile/status/cc/converge operations cannot silently remove it
- recursive evidence collection is bounded by an explicit max_files value

TARGET B — DECLARED-EVIDENCE REFERENCE VALIDATION

A stronger invariant is also required.

If authoritative SAIPEN state references an evidence path, for example:

.saipen/evidence/PERF-001_WINDOWS_EVIDENCE.md

from LOG, coverage, STATE, BOARD or another authoritative closure record,
the exporter must detect when that referenced file is absent from the archive.

The following state must be impossible:

authoritative closure references evidence file
+
archive omits evidence file
+
required_evidence_omitted = false

Prefer explicit referenced-evidence discovery rather than assuming directory
collection alone proves completeness.

TARGET C — RED CONTROL FOR MANIFEST REGENERATION

Add a deterministic regression:

1. create project with `.saipen/evidence/proof.md`
2. reference proof.md from closure coverage/log
3. generate/refresh `.saipen/MANIFEST.json`
4. run lifecycle operations that regenerate protocol metadata
5. regenerate MANIFEST again
6. verify evidence/ remains declared
7. pack project
8. verify ZIP contains proof.md
9. verify manifest accounting reports complete

Pre-fix red control must demonstrate the current failure:
local/generated contract loses evidence/ after canonical regeneration.

TARGET D — FALSE-COMPLETE RED CONTROL

Create a second regression:

1. closure metadata references `.saipen/evidence/proof.md`
2. deliberately omit proof.md from exported ZIP
3. exporter/accounting MUST report omission/incomplete
4. `required_evidence_omitted` must become true or equivalent authoritative
   incomplete state must be emitted

Do not allow evidence_files_collected == evidence_files_in_archive to imply
completeness when the discovery set itself is incomplete.

TARGET E — BACKWARD COMPATIBILITY

Verify projects without `.saipen/evidence/` still export normally.

Do not make the directory mandatory merely because no evidence artifact has
ever been produced.

The directory is an authoritative conditional surface:
if present/referenced, collect and account for it.

VALIDATION

Run focused manifest/generator tests.
Run AUDAPACK collector/export tests.
Run SAIPEN validator tests.
Run lifecycle/reconcile regeneration tests.

Then reproduce against Problip or an equivalent fixture:

- evidence file exists
- generated `.saipen/MANIFEST.json` declares evidence/
- archive contains evidence file
- archive/source hash equality holds
- subsequent SAIPEN lifecycle command does not erase evidence/ declaration
- second archive still contains evidence
- required_evidence_omitted remains false only when evidence is genuinely present

NON_GOALS

Do not modify Problip production code.
Do not recreate PERF-001.
Do not special-case the filename PERF-001_WINDOWS_EVIDENCE.md.
Do not patch only one generated project MANIFEST.
Do not weaken existing evidence accounting.

ACCEPTANCE

DONE only when:

- canonical SAIPEN source owns the evidence/ declaration
- regenerated project manifests retain evidence/
- referenced missing evidence is detected
- AUDAPACK cannot return false COMPLETE for this class
- regression covers regeneration, not only initial packing
- Problip-style closure evidence survives repeated lifecycle/export cycles
