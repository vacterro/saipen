## 1. Non-negotiable invariants

I1. Only canonical, operation-backed transactions may authorize lifecycle state changes. A file's shape is not its authority.
I2. A model's assertion, CLI spelling, user-like text, or edited `BOARD.md` cannot mint operator permission, ownership, or DONE.
I3. A process that shares the same writable OS identity as an agent is not a security boundary. Native Windows ACLs must be evaluated with a separate standard-user identity and broker; fail safely when unavailable.
I4. Legitimate code editing remains possible when independently admissible; invalid history blocks unsafe canonical mutation, not automatically unrelated read-only work.
I5. Unknown/unproven host capabilities must be reported as ADVISORY/UNAVAILABLE, never mechanically enforced.
I6. Recovery cannot create missing historical events, silently erase evidence, or accept unbacked closures as DONE.
I7. Tests never mutate real user profiles, live Scheduler tasks, physical project ledgers, or production kill authorization.
I8. All protected-write tests include denial, allowed canonical write, interruption, tamper, and rollback variants.
I9. No automatic push, tag, publish, authorization-policy choice, or live destructive operation.
I10. Never run two agents in the same source-write corridor without verified separate worktrees and canonical ownership.
