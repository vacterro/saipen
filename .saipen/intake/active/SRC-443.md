# 5. P0-B — PROCESS-TREE WATCHDOG NOT FULLY BOUNDED

## Confirmed source issue

В `run_floor_once()` создаётся обычный `subprocess.Popen()` без отдельной process group/session.

Затем используется:

```python
watchdog = threading.Timer(
    window,
    _terminate_process_tree,
    [process],
)
```

И:

```python
stdout, stderr = process.communicate()
```

В POSIX-ветке `_terminate_process_tree()` пытается вызвать `os.killpg(process.pid, ...)`.

Если процесс не является лидером отдельной группы, group kill может не сработать. Fallback завершает только непосредственный процесс.

Grandchildren могут продолжать удерживать pipe descriptors.

Это оставляет `communicate()` в ожидании после истечения объявленного deadline.

## Independent reproduction

На извлечённом source code создан контролируемый test:

- Window: 1.0 s.
- Parent Python process.
- Grandchild, удерживающий stdout/stderr.
- Grandchild завершает работу самостоятельно.

Observed:

```text
configured_window: 1.0 s
actual_wall:       5.691 s
result:            TIMEOUT
```

Следовательно, реальное bounded execution не гарантировано на проверенной POSIX-платформе.

Это не доказательство того же дефекта в Windows Job Object path. Windows нужно проверить отдельно.

## Required repair

Использовать platform-correct process ownership.

Для POSIX исследовать:

- создание отдельной process session/group;
- group termination;
- bounded escalation TERM → KILL;
- гарантированное завершение pipe readers;
- безопасное закрытие streams;
- handling of already-exited children;
- race between process exit and watchdog.

Для Windows:

- exact owned process tree;
- Job Object semantics или поддерживаемый `taskkill /T`;
- bounded termination;
- inherited handles;
- process creation identity.

Нельзя завершать чужие процессы по одному PID.

## Required negative controls

1. Normal immediate completion.
2. Timeout before child spawn.
3. Parent with grandchild holding stdout.
4. Multiple descendants.
5. Child ignores graceful termination.
6. Parent exits but grandchild stays alive.
7. Process exits during watchdog activation.
8. PID reuse.
9. Cancellation.
10. Unrelated process remains untouched.

## Acceptance

Настоящее wall time должно соответствовать declared timeout + документированному небольшому cleanup allowance.

Измерить p50, p95, max и отсутствие persistent owned orphans.

Не заявлять bounded execution без проверки процесса с grandchildren.
