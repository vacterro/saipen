ROOT CAUSE

This is not a missing-file defect.

This is an artifact-reference semantics defect.

SAIPEN already has related invariants:

1. ADR-0003 separates transport location from execution/project identity.
2. BOOT says handoff prose is not authority.
3. audit_manifest.py explicitly states that a hypothetical path in a handoff is not proof that evidence exists.
4. Source bodies are DATA and do not gain execution authority merely by containing command-looking or path-looking text.

The missing invariant is the equivalent rule for external artifact references:

A filename/path/URL mentioned in an audit, handoff, report, source body, or explanation is not automatically an execution dependency.

Today that semantic gap allows a model to promote an incidental filename into an invented operator blocker.

TARGET BEHAVIOR

Introduce one canonical protocol contract for external artifact references.

Suggested rule owner name:

ARTIFACT-REFERENCE-01

The exact identifier may differ if repository conventions indicate a better owner, but there must be one canonical owner and no duplicated prose implementations.

CORE RULE

Artifact mention is not artifact dependency.

A bare filename, path, URL, archive name, screenshot name, bundle name, or other artifact locator occurring in prose defaults to non-required provenance/context.

It may become a required execution input only through explicit dependency semantics.

The system must distinguish at least these meanings:

PRIMARY_TARGET
The artifact itself is explicitly selected by the operator as the thing to inspect/modify/audit.

SUPPLEMENTAL_CONTEXT
The artifact adds useful information to a different primary target.

REPLAY_EVIDENCE
An upstream stage already consumed the artifact and the current handoff contains the normalized findings/requirements needed downstream. The original artifact is useful for replay or deeper verification but is not required for ordinary continuation.

REQUIRED_INPUT
The bytes are genuinely required to perform or verify the current Work and no authorized substitute carries the needed information.

The exact enum names may differ, but the distinction must be durable and unambiguous.

DEFAULT PROMOTION RULE

Untyped prose references MUST NOT become REQUIRED_INPUT.

Examples that remain non-required by default:

"Found in foo.zip"
"See screenshot.png"
"Audit used build_bundle.zip"
"Archive foo.zip contained 12 findings"
"Generated from report.pdf"

A reference becomes REQUIRED_INPUT only when the current authoritative request or a machine-owned structured contract explicitly says that the artifact bytes are required.

Do not infer requiredness from:

- filename presence;
- an absolute or relative path appearing in prose;
- a .zip/.pdf/.png extension;
- words such as "archive", "bundle", "attachment", or "file";
- the fact that an upstream audit named the artifact;
- a previous machine-local location.

UPSTREAM-CONSUMED ARTIFACT RULE

When an upstream auditor/reviewer has already consumed an artifact and emitted a complete downstream repair handoff containing the actionable findings, that source artifact defaults to REPLAY_EVIDENCE.

The downstream implementation agent must work from the normalized handoff.

It must not ask the user for the original artifact merely because the handoff names it.

Promotion back to REQUIRED_INPUT is allowed only when the downstream task actually needs facts that the handoff did not preserve.

TARGET-SELECTION RULE FOR MULTIPLE UPLOADS

When a project/repository snapshot and a FastPrompter selection/silo bundle are supplied together:

- explicit operator target selection wins;
- otherwise the actual project/repository snapshot is the PRIMARY_TARGET;
- a FastPrompter selection_bundle is SUPPLEMENTAL_CONTEXT by default;
- bundle contents may alter requirements for the primary target but do not replace the target;
- do not mistake a self-contained requirements bundle for a project repository merely because both are ZIP files.

When only the bundle is supplied and the operator explicitly asks to audit the bundle itself, it may be PRIMARY_TARGET.

Filename suffixes such as "_bundle.zip" are hints only, never authority. Prefer manifest facts such as producer and bundle_kind when bytes are available.

NO-QUESTION RULE

A missing SUPPLEMENTAL_CONTEXT, REPLAY_EVIDENCE, PROVENANCE_ONLY, or other non-required artifact:

- MUST NOT create WAIT_USER;
- MUST NOT create BLOCKED;
- MUST NOT create OPERATOR ACTION;
- MUST NOT ask for a local path;
- MUST NOT stop otherwise runnable Work.

The agent may record a diagnostic that optional replay context was unavailable, but execution continues.

A missing REQUIRED_INPUT may become a true blocker only after deterministic self-resolution has failed and the missing bytes are materially necessary.

Even then, do not ask "where is file X?" merely because X appeared in prose.

Report the exact missing required artifact identity and why its bytes are indispensable.

DETERMINISTIC SELF-RESOLUTION

Before any human boundary for an explicitly REQUIRED_INPUT artifact, attempt only bounded authoritative carriers.

Recommended precedence:

1. Current explicitly supplied attachment/artifact carrier.
2. Exact source receipt or durable SAIPEN evidence already containing the bytes.
3. Explicit path carried by the current authoritative request.
4. Exact project-local declared artifact reference.
5. Producer-specific locator carrier when one is explicitly available and verifiable.
6. Structured failure.

Do not recursively scan arbitrary drives, the user's home tree, Downloads, temporary folders, or unrelated repositories by basename.

Do not guess paths.

A filename-only search across the machine is not recovery.

IDENTITY PRECEDENCE

When stronger identity exists, basename is merely display metadata.

Preferred match authority:

1. cryptographic archive digest when the contract requires exact archive bytes;
2. producer logical content fingerprint when identifying equivalent logical bundle content;
3. explicit producer artifact ID;
4. exact bound path only as a local navigation hint;
5. basename last, and never as unique identity.

If the same logical bundle arrives as:

foo_bundle.zip
foo_bundle(2).zip
foo_bundle_2.zip

and a verified fingerprint proves equivalent content, they are the same logical source for dependency-resolution purposes.

If the basename is identical but the digest/fingerprint differs, they are different artifacts.

DISPOSITION INTEGRATION
