SAIPEN

APPEND — FREEBUFF MANUAL LIFECYCLE BYPASS / MISSING-CLI MUST NOT DEGRADED-WRITE STATE

PRIORITY

P0 protocol-integrity regression.

REAL INCIDENT

A FreeBuff executor operated inside a SAIPEN-managed project.

The agent reported:

"The saipen CLI is not installed on this host (saipen --version -> command not found), so the lifecycle records were written by hand against the RFC field shapes rather than through supported SAIPEN operations."

Despite the missing canonical SAIPEN runtime, the agent then:

- marked the ticket DONE;
- updated STATE;
- wrote BOARD/LOG lifecycle state manually;
- committed repository changes;
- pushed to main;
- waited for CI;
- reported successful terminal lifecycle.

This is unacceptable.

The fact that the agent disclosed the limitation does not make the resulting lifecycle valid.

ROOT DEFECT

There are two independent failures.

A. HOST / BOOTSTRAP FAILURE

The FreeBuff execution environment could not resolve a canonical SAIPEN control-plane route.

`saipen` was unavailable on PATH and no automatic compatible runtime/bootstrap path recovered execution.

B. PROTOCOL-INTEGRITY FAILURE

After canonical control access was unavailable, the executor was still able to continue by manually mutating SAIPEN lifecycle files.

The system therefore degraded from:

managed lifecycle

into:

model-authored lifecycle prose stored in canonical files.

That must never be an allowed fallback.

CORE INVARIANT

If a project is SAIPEN-managed:

NO EXECUTOR MAY SUBSTITUTE DIRECT STATE/BOARD/LOG EDITS FOR CANONICAL SAIPEN OPERATIONS.

Missing CLI/control-plane access is an executor/runtime incompatibility.

It is not authorization to manually perform lifecycle transitions.

Correct behavior:

SAIPEN control unavailable
-> recover compatible runtime/control route
-> otherwise fail over executor
-> otherwise BLOCKED / WAIT_EXTERNAL according to canonical policy

Never:

SAIPEN control unavailable
-> edit STATE.md
-> edit BOARD.md
-> append LOG.md
-> continue as if canonical transition occurred.

MANUAL LIFECYCLE MUTATION CLASS

Introduce or reuse a canonical violation classification, conceptually:

MANUAL_LIFECYCLE_MUTATION

or:

UNAUTHORIZED_CANONICAL_STATE_WRITE

It must apply when an executor directly modifies protected lifecycle authority outside supported operations.

At minimum protect canonical ownership of:

- .saipen/STATE.md
- .saipen/BOARD.md
- .saipen/LOG.md
- lifecycle/event journals
- canonical evidence indexes where operation ownership already exists
- other machine-owned lifecycle records

Do not block legitimate SAIPEN engine writes.

Do not rely only on prompt instructions.

HOST RECOVERY FIRST

Before classifying the executor unusable, FreeBuff should run the existing bounded bootstrap chain.

Expected conceptual sequence:

1. detect SAIPEN-managed project;
2. attempt canonical `saipen continue --json`;
3. if command missing:
   - inspect project bootstrap authority;
   - resolve compatible machine/runtime authority;
   - use account-accessible runtime/broker/projection;
4. verify protocol/runtime compatibility;
5. invoke canonical control operation;
6. only then continue Work.

Do not perform broad filesystem hunting.

Do not clone arbitrary GitHub HEAD.

Do not request broad ACL access.

Use the already-designed machine/runtime bootstrap authority.

FREEBUFF-SPECIFIC INGRESS

This incident proves that the internal SAIPEN contracts are still not wired end-to-end into the real FreeBuff host/executor path.

Locate the actual FreeBuff / SAIRoute / SAIOPP ingress used for this run.

The repair must ensure BEFORE implementation handoff that the session has:

- SAIPEN control-plane access;
- required repository capabilities;
- required shell/process capabilities if applicable;
- canonical lifecycle write authority through SAIPEN, not direct file mutation.

If FreeBuff lacks SAIPEN control:

reject/fail over before the agent begins managed Work.

Do not wait until the model discovers this after receiving the project.

DIRECT WRITE GUARD

Add a mechanical guard where feasible.

The goal is that agent-level file operations cannot silently impersonate the SAIPEN engine.

Possible approaches include:

- protected-path write interception;
- canonical write token/lease;
- operation-owned write context;
- post-write provenance validation;
- immutable/journal signature ownership;
- host-side deny rules for protected lifecycle files.

Implementation choice is repository-owned.

The important invariant:

ordinary executor file-edit tools must not be able to perform a valid lifecycle transition by directly changing canonical files.

If direct writes happen anyway, validation must mark the project as tampered/untrusted rather than accepting the new state.

PROVENANCE

Canonical lifecycle mutation should be attributable to a supported operation.

A valid lifecycle event should have enough machine provenance to prove:

- operation identity;
- run/ticket;
- transition;
- event ID;
- writer/runtime generation;
- expected state digest or equivalent integrity binding.

Do not accept:

"the Markdown fields look structurally correct"

as proof that a lifecycle transition was canonical.

The incident explicitly demonstrates why RFC-shaped bytes are not sufficient authority.

TERMINALITY MUST FAIL CLOSED

If an agent manually writes:

phase: DONE

without a canonical DONE operation, SAIPEN must not consider the Work terminal.

Likewise:

manual BOARD status DONE
manual LOG event
manual STATE last_event

must not synthesize canonical completion.

Validation should produce a hard failure such as:

UNAUTHORIZED_LIFECYCLE_WRITE

until repaired/reconciled through supported recovery.

PUBLISH SAFETY

A SAIPEN-managed project must not reach publish/release authorization based on manually mutated lifecycle state.

In this incident the agent pushed to main after manually fabricating lifecycle continuity.

Future expected behavior:

canonical control unavailable
-> publication authority unavailable

unless publication is independently operator-authorized outside SAIPEN policy.

Do not infer publish permission from hand-written DONE state.
