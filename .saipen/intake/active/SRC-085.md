MILESTONE 2 — IMPROVE append_run MUST NOT POISON IMMUTABLE REPORTS

==================================================

AUDAPACK reproduction:
append_run accepts run_text already beginning with:
## RUN N
while append_run itself also owns RUN heading construction.

The committed report then contains duplicate RUN identity and becomes
uncompletable.

Because reports are append/immutable, abort becomes the only escape.

Fix this BEFORE write.

Preferred contract:
append_run receives RUN BODY, not a complete RUN section.

Before mutation:
parse/validate proposed body.

If it contains a RUN heading owned by append_run:
either:
A. reject with a stable code before any write;
or
B. normalize exactly one redundant leading heading only if that behavior is
explicitly defined and unambiguous.

Reject is simpler and safer.

Do not repair already-committed immutable report bytes in place.
