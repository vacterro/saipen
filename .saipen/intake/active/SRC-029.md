SAIHANDOFF: Detached handoff project binding: host-session project-root carrier and identity preservation

SAIHANDOFF

PROJECT: SAIPEN
MODE: IMPLEMENT
PRIORITY: P0
TARGET_CLASS: BOOTSTRAP / PROJECT BINDING / HOST ENFORCEMENT

USER INCIDENT

A handoff was opened for an agent from the intended project context, but the host staged the handoff file under:

V:_TEMP_\fastprompter_drag\SAIHANDOFF_20260912_0418.md

The agent then observed:

Running in V:_TEMP_\fastprompter_drag

and executed:

git rev-parse --show-toplevel
git status --short --branch

Both correctly failed because the staging directory is not the project repository.

The agent then asked the user:

"What is the SAIPEN Git worktree root containing `.saipen/`?"

This question must not be necessary when the launching workflow already knew the intended project.

ROOT CAUSE

Current project binding authority resolves:

1. explicit --project-root;
2. Git worktree;
3. Git common/main worktree;
4. nearest ancestor carrying .saipen.

A detached handoff staging directory satisfies none of these.

The handoff transport currently loses the project-root provenance that existed before staging.

This is not a Git discovery bug.

This is a missing PROJECT BINDING CARRIER between the launcher/handoff transport and SAIPEN bootstrap.

IMPORTANT ARCHITECTURAL CONSEQUENCE

The planned universal SAIPEN enforcement/guard work depends on solving this first.

A guard invoked from a detached staging cwd would otherwise observe:

NOT_SAIPEN_PROJECT

and incorrectly treat the invocation as outside SAIPEN.

Therefore detached-handoff project binding is a prerequisite of machine-enforced SAIPEN admission.

MILESTONE 3 — HOST/SESSION PROJECT-ROOT CARRIER

Add a session-scoped project-root carrier for host integrations.

Preferred contract:

SAIPEN_PROJECT_ROOT

Optional integrity companion:

SAIPEN_PROJECT_LINEAGE

These are host/session inputs, not durable project truth.

Resolution precedence must become:

1. explicit --project-root
2. verified host/session project-root carrier
3. Git worktree
4. Git common/main worktree
5. nearest ancestor .saipen
6. refusal

Do not scan arbitrary drives looking for projects.

Do not infer a project from basename alone.

Do not choose the only `.saipen` directory found somewhere on disk.

A wrong root is worse than asking.

HOST ROOT VALIDATION

When SAIPEN_PROJECT_ROOT is present:

* expand and normalize the path;
* require an existing directory;
* require a real owned .saipen directory;
* read .saipen/IDENTITY.md;
* if SAIPEN_PROJECT_LINEAGE is supplied, require an exact lineage match;
* on mismatch, fail closed;
* do not silently fall back to ambient CWD after an explicit host binding failed.

Return a specific structured refusal such as:

PROJECT_BINDING_INVALID
PROJECT_LINEAGE_MISMATCH

Reuse an existing exact code if the vocabulary already owns the meaning.

MILESTONE 6 — LOCAL SAIHANDOFF LAUNCH ENVELOPE

Define a LOCAL transport envelope for handoff launchers.

This is separate from durable SAIPEN source/brief authority.

The local envelope may carry:

project_root_hint

Example semantics only:

Do not treat project_root_hint alone as portable truth.

The launcher should set:

before spawning the agent.

The handoff payload may live anywhere, including a temporary staging directory.

The agent's process cwd is then no longer the only project-binding channel.

MILESTONE 7 — PRESERVE PROJECT CWD WHEN POSSIBLE

The producer/launcher side should not change the agent working directory to the handoff staging directory merely because the handoff file lives there.

Preferred launch behavior:

working directory = intended project root

The payload location and project working directory are two different things.

If the host requires a staging cwd, the session root carrier from Milestone 3 becomes mandatory.

This part may require a corresponding FastPrompter-side patch.

Do not hide that cross-project dependency.

SAIPEN owns the consumer contract.
The launcher owns preserving/providing the root.

ACCEPTANCE

The reported incident is fixed when this sequence becomes possible without a user question:

1. User launches an agent for a SAIPEN project.
2. Host stages SAIHANDOFF_*.md under a temporary directory.
3. Agent process may have staging as cwd.
4. SAIPEN receives the verified project binding from the launch transport.
5. BOOT binds the intended project automatically.
6. STATE/BOARD/LOG are loaded from the intended project.
7. A foreign/stale/mismatched binding fails closed.
8. No second .saipen is created.
9. The temporary handoff directory is never mistaken for project identity.
10. The future admission guard protects the intended project even from detached staging cwd.

FINAL PRINCIPLE

The location of the handoff file is transport state.

The location of the project is execution state.

They must never again be inferred to be the same thing.
