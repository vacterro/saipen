2. ROOT CAUSE — INTERACTIVE DESKTOP
============================================================

Investigate why the live acceptance harness reports:

BLOCKED_ENVIRONMENT
interactive desktop unavailable

A visible GUI on the operator's desktop does not imply
that the agent's worker process shares that desktop.

Inspect the real test process:

- Windows user SID.
- Process session ID.
- Active console session ID.
- Window station.
- Thread desktop.
- Foreground window visibility.
- Desktop access rights.
- Parent launcher identity.
- Actual target console HWND and owning PID.

Do not use GetFocus() alone to determine whether an
interactive desktop exists.

Distinguish:

A. Actual noninteractive worker/session.

B. Wrong desktop or window station.

C. False-negative interactive desktop detector.

D. Invalid console ownership binding.

E. Input rejected by Windows security boundaries.

F. Installed runtime generation mismatch.

Record direct evidence for the classification.

Do not bypass Windows input isolation.
