instead, received `NO_HOME` from it, changed into the SAIPAL repository, ran

The witness statement also claims ~40 accepted session bundles, a session index
reaching 1019, and five `NO_DRIFT` candidate receipts. Those claims are
**self-report**, handled separately in §9 and deliberately not promoted to fact.

## 4. The defect that actually belonged to SAIPEN

Not the launcher. Not the skill install. The **refusal surface**.

Before this repair, SAIPEN answered a foreign protocol command exactly as it
answered a typo:

```
saipen saipal continue --json  ->  {"code":"VALIDATION_FAILED","detail":"unknown command: saipal"}   exit 2
saipen bogusxyz --json         ->  {"code":"VALIDATION_FAILED","detail":"unknown command: bogusxyz"} exit 2
```

Byte-identical in shape. A model that had just been told to run a SAIPEN
command, and had a SAIPAL skill in front of it, received no signal that the
token it was holding belonged to a *different protocol*. The subsequent step —
"SAIPAL said NO_HOME, so let me go find SAIPAL's home" — is a rational response
to an uninformative refusal. This is the same defect class the file already
names at `tools/saipen.py:15417` ("never `unknown command`, which invites a weak
model to improvise a substitute", AUTO-003) and in
`tools/saipen_engine/command_effects.py:247` (T-1767).

## 5. Root cause classification

**MULTI_CAUSAL_FAILURE**, with a clear ownership split:

| Layer | Classification | Owner |
|---|---|---|
| Cross-protocol ambiguity in SAIPEN's own refusal | **COMMAND_ROUTER_DEFECT** | SAIPEN (repaired here) |
| Host skill inventory offering both protocols for one token | **INVENTORY_DESYNC** | FREEBUFF OWNER (§11) |
| Model substituting a similar protocol after a refusal | **MODEL_EXECUTION_DRIFT** | mitigated, not eliminated (§10) |
| SAIPAL accepting ingestion in that state | **CROSS_PROJECT_BINDING_DEFECT** | SAIPAL OWNER (§9) |
| Native operator-origin proof | **INSUFFICIENT_EVIDENCE / NOT_INSTALLED** | FREEBUFF OWNER (§12) |

The launcher and the SAIPEN skill install are **not** causes. Both were measured
healthy. Blaming either would have produced a repair that fixed nothing.

## 6. Implemented correction

An explicit protocol command now keeps its owner (EXACT-NAMESPACE-01):

1. `saipen/REGISTRY.json` gains `exact_namespace.foreign_protocols`, the machine
   authority for foreign ownership. Prose is never parsed.
2. `saipen_engine/commands.foreign_protocol_owner()` resolves a token against
   that declaration, including declared aliases, case- and space-insensitively.
   A damaged registry returns `None` and degrades to the old refusal rather than
   inventing an owner.
3. `tools/saipen.py` refuses an owned token with `FOREIGN_PROTOCOL_COMMAND`,
   naming the protocol, the **full** invocation, the route to run instead, and
   the standing rule that `NO_HOME` is never repaired by changing directory,
   searching for a home, or creating one.

No SAIPEN command was removed or renamed. No SAIPAL operation was modified or
disabled. A deliberate, independent SAIPAL request remains legal and is recorded
as such in `legitimate_use`.

## 10. Honest limits of this repair

These tests are UNIT and CONTRACT controls over SAIPEN's refusal surface. They
prove the refusal is typed and specific; they **cannot** prove what a host's
skill picker offers a model, and they cannot stop a model from ignoring a
refusal. `INSTALLED_HOST` and `LIVE_END_TO_END` acceptance needs a real FreeBuff
run, which is the receiving owner's work. No native pre-render interception
exists for this host: `registry.json` declares FreeBuff
`response_enforcement: ADVISORY`, `pre_output_interception: NONE`,
`prompt_to_work_binding: NOT_INSTALLED`. This audit does not claim otherwise.

## 11. FreeBuff owner handoff

Required, under separate FreeBuff authority:

1. Exact namespace ownership before semantic skill matching: an explicit
   `/saipen <cmd>` must never be dispatched to a skill whose name merely
   resembles it.
2. Never present SAIPAL as a candidate for an explicit SAIPEN command.
3. A refusal from one protocol must not trigger a working-directory change into
   another protocol's repository.
4. Re-read `~/.agents/skills/` on session start so a stale inventory cannot map
   a namespace to the wrong owner.

## 12. Native operator-origin provenance — separately classified

`SAIPAL` recognition is not authorization. Per T-1819/T-1822 and the adapter
registry, FreeBuff supplies **no** independently authenticated operator event:
`host_prompt_available: false`, `witness_without_launch_carrier:
model_supplied`, `supported_carrier_mechanisms: []`. The incident's request is
`request_witness: model_supplied` and is **not** upgraded by this audit. The
required native chain (human UI event → trusted input boundary → exact bytes and
digest → event/session/project binding → broker-issued origin receipt → worker
registration → model tool call → SAIPEN verification) remains NOT_INSTALLED and
is a FreeBuff-owner implementation item.
