# PY-16: close the TEST-13 S8 reproduction (duplicate crew_run receipt)

Target: `tools/saipen_engine/crew.py`, cloned byte-exact into `kitchen/pen/`
(sha256 verified identical before editing). Edit lives only in the copy; the
project tree was never written to.

## The reproduction being closed

TEST-13 S8: `python -B tools/saipen.py crew record-run saihunt --json` run twice
exits 0 both times and writes TWO COMMITTED crew_run receipts for the same
epoch, role and package identity -- `.saipen/LOG.md:1582` (E-20907, op
crew-run-b714715fb29f4a6e9cd77d4fbc17647e) and `.saipen/LOG.md:1583` (E-20908,
op crew-run-8d68e46e70e94e239c8d91392652267b). Defect class: order and
repetition -- a retry of an unchanged binding silently doubles the evidence.

## The patch

`kitchen/pen/PY-16.patch` (48 added lines, nothing removed or rewritten):

1. new private helper `_duplicate_crew_run(root, records, epoch_op_id,
   role_name, identities)` -- returns the op_id of an already COMMITTED
   crew_run receipt binding the same epoch, the same role and the same package
   identity SET (order-insensitive, because ordering is not evidence);
2. in `crew_record_run`, after the NO_READY_PACKAGE check, the guard runs and
   refuses with `DUPLICATE_CREW_RUN`, naming the existing receipt op id, before
   `record_crew_run` is reached;
3. the existing `package_identities=[...]` comprehension is hoisted into the
   `identities` list so the guard and the writer see the same bytes.

No behavioural change on a first binding, no signature change, no new
dependency.
