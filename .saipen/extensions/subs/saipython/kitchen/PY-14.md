The detector previously matched every numeric keyword named timeout. It
therefore rejected thread.join(timeout=5) in server cleanup. T-1347 already
owns the defect; TEST-11 reproduced the one failing suite check.

The proposed change resolves subprocess imports, including aliases, and
syntactically bound Popen receivers before examining timeout keywords.
run, Popen, check_output, check_call, call and Popen.communicate remain in
scope. Thread joins and unrelated run/communicate methods are excluded.
Existing suppress-block and numeric-floor rules are unchanged.

Validation against the pen module, with its HOME/TOOLS bound read-only to the
real repository so the unchanged suite scans the actual test corpus:

- Original: 9 tests, 1 failure, 1 explicit opt-in soak skip.
- Patched: 10 tests, 0 failures, 1 identical opt-in soak skip (1.918s).
- Same-verifier control: the new thread-join assertion fails when the pen
  test is run with the original detector substituted; exactly one expected
  assertion failure, no errors. The patched detector passes that assertion.
- Subprocess red control remains active; alias, direct/context/attribute
  Popen receiver cases are covered. Unrelated methods stay unreported.
- Ruff: all checks passed. `git apply --check` accepts PY-14.patch.

Limit: this is bounded syntactic receiver analysis, not whole-program Python
data flow. Dynamic dispatch and arbitrary receiver reassignment are outside
its proof. The opt-in concurrent full-suite soak was not run.

Only the pen copy was edited. Core must review and integrate under T-1347;
this package does not close that ticket or claim publication.
