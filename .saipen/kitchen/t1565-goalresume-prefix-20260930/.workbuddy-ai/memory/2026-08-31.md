**Key analytical conclusion (reusable):**
MCP token economy has a BREAK-EVEN, not a free win. Every MCP tool schema is re-injected on EVERY turn.
~15 tools ~= 2,000-2,500 tokens/turn of standing overhead. Break-even sits around ~30k LOC of *code*
for a ~30-turn session. Below that (or on short sessions) it is a NET LOSS. The real compounding win is
the persistent SQLite index: sessions 2..N skip re-exploration entirely.

**CRITICAL BUG FOUND IN SAIPEN REPO — indexing the repo root FAILS:**
- `index_repository` on V:\...\_SAIPEN returns status:error "Pipeline failed"
- Root cause: a 0-byte file literally named `nul` in the repo root (classic `echo > nul` accident).
  Windows resolves it to a device; os.stat gives st_mode=0o20000 (S_IFCHR) instead of 0o100000 (regular).
  The tree-walker aborts the entire run.
- PROVEN by bisect: every top-level subdir indexes fine (tools 3085 nodes/19604 edges,
  tests 957, saipen 384, extensions 309, bootstrap 86, guides 198, KNOWLEDGE 50, .codenomad 94,
  _todelete/assets/audit 2 each). Only the root fails.
- Also PROVEN by rename: with `nul` moved aside, the root indexes OK.
- Windows REFUSES to rename anything back to `nul` (WinError 5). Extended `\\?\` prefix is
  required to address the file at all; os.rename away works, os.rename back does not.
- `git ls-files nul` -> not tracked. It is untracked 0-byte junk.
- CURRENT STATE: the file now exists as `_nul_probe_tmp` in the SAIPEN root (0 bytes, same content).
  Left for the user to decide: delete it, or leave the new name. Deleting is recommended.

**PowerShell gotchas hit (reusable):**
- `Add-Member -NoteValue` does NOT exist. Use `-MemberType NoteProperty -Name X -Value Y`.
- The agent's PowerShell tool returns NO stdout. Capture with Start-Transcript to a file, then Read it.
- Git Bash heredocs mangle `\\?\` (backslashes -> forward slashes). Write Python to a FILE and run it.
- Git Bash blocks `powershell ...` ("bypass security checks") — use the PowerShell tool.
- Bash tool blocks commands containing the word `function` (safe-delete heuristic false positive).
- The agent's PowerShell has a global Remove-Item safe-delete wrapper: paths under %TEMP% are

**WHITELIST MECHANISM - use `allow-root`, NOT `CBM_ALLOWED_ROOT`:**
- `codebase-memory-mcp allow-root <path>` records a root (persisted, additive)
- `codebase-memory-mcp allow-root --list` shows them
- also `--approve-manifest <project>`, `--approve-sensitive`
- **`CBM_ALLOWED_ROOT` env var takes ONE path only.** A `;`- or `,`-separated
  list makes the daemon die with "daemon-backed CLI execution failed". Tested.
- **THE TRAP:** zero roots recorded = indexing UNCONFINED (anything goes).
  One or more recorded = CONFINED to only those. Recording the first root
  silently breaks every other project with "outside the allowed root".
- Stored as plain text, one path per line, at
  `%LOCALAPPDATA%\codebase-memory-mcp\cache\allowed_roots` (127 bytes for 3).
  Travels with CBM_CACHE_DIR. Trivial to back up / restore / version.
