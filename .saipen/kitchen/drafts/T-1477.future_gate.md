## What the reference is

Oper is a written constitution for one engineering agent plus a curated library of
97 skills. `AGENTS.md` is the root: an owner priority ladder, a mandatory premise
check before any plan, a ten-step task cycle, a never-destroy rule, a commit reflex,
a truthfulness contract and an index-first discovery order. `docs/` holds ten
normative documents (Principles, Governance, Code, Data-Safety, Version-Control,
Working-Base, Autonomy-Charter, Infrastructure, KB-RAG, Skills). `BIRTH.md` is a
first-run onboarding interview that personalises the workspace and then deletes
itself. It is prose-and-discipline driven: almost nothing is enforced by an engine,
which is the main difference from SAIPEN, where lifecycle, evidence and ownership are
machine-owned.

## Eligibility -- when SAIPEN is "whole enough"

The operator's condition is made measurable so no agent has to judge it by feel. All
four must hold at the time of adoption:

1. The T-1446 24H unattended gate has PASSED on a rerun after T-1476 (the first run
   stopped at 15661 s with NO_PROGRESS_LOOP).
2. The declared core-unit family gate (T-1344) is in force and T-1472 has made a full
   proof materially cheaper than 2254 s.
3. No P1 Work is open in DOING or TODO.
4. The quality-retention matrix (T-1464) has run at least once, so an adopted
   mechanism can be checked for not lowering quality on weaker models.

Row 1 is the exception: it names a defect measured in this repository (E-8317), so it
may be proposed as ordinary Work earlier, through normal intake, with its own evidence.

## Adoption rule

One mechanism at a time, through the external-mining bench: the unit of adoption is a
single mechanism with an owner, a failure semantics and a defect class it removes,
never the reference project. Each adoption is its own Work with red-then-green
evidence. Nothing here authorises a protocol, engine or document change today.
