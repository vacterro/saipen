# Ordinary-phase 30% target: bounded owner split candidate

This is read-only design evidence while T-1857 full5 runs. No protocol source or load profile changed.

Current declared `ordinary_phase` route in `REGISTRY.json` loads `CORE.md` plus `@active_phase_max`. LF-normalized sizes on the frozen tree: CORE 32,117 bytes; largest phase VERIFY 8,826; total 40,943. A 30% reduction needs at most 28,660 bytes, so at least 12,283 bytes must leave that mandatory route. The two candidate CORE sections total 13,524 bytes: §1.2 File Model 9,429, §1.10 Command Surface 4,095. Their replacement CORE anchors together may use at most 1,241 bytes to meet the numeric target. This is a necessary byte calculation, not permission to weaken a rule.

Owner fit: `COMMANDS.md` already owns command semantics and is 6,134 bytes; it can hold §1.10 while staying below the unchanged 51,200-byte single-document cap. `OPS.md` is 49,935 bytes and cannot absorb §1.2. The file model needs a distinct conditional owner (for example `FILE_MODEL.md`) or a rigorously proven split among existing owners. CORE must retain the global checkpoint, state, BOARD and LOG invariants as concise normative anchors, and the detailed clauses/Rule IDs must remain verbatim or semantically equivalent at an owner that the actual mutation and rule-question routes load.

Before any source edit, prove that the ordinary phase route does not require the detailed file model or full command surface unconditionally. Check BOOT/INDEX/REGISTRY `must` and `requires`, installation manifest, command resolution and checkpoint callers. A profile-only deletion, a raised budget, or hiding obligations in an unreferenced appendix would be a false reduction. The split must preserve all unknown-field, timestamp, parent-chain, ownership, blocker, receipt, confirmation, recovery, retention and command refusals. Then measure actual route load bytes, inspect old/new rule-owner and caller mappings, run focused red/green controls for each moved contract, and run the full family once on the final source generation.

The current CORE text and existing owner map are the before-image. The measured target is still unmet; this candidate neither closes SRC-289:R013 nor authorizes T-1857 completion.

Reference inspection raises the migration cost: `README.md`, `RFC.md`, sub-protocol docs, STYLE, MAINTENANCE, engine comments, tests and `tools/validate.py` cite CORE §1.2 or §1.10 directly. The validator checks the `saipen/CORE.md#110-command-surface` README anchor and several exact CORE §1.2/§1.10 cross-document contracts. REGISTRY maps `STATE-SHAPE-01`, `STATE-NEXT-01` and `EVIDENCE-RETENTION-01` to CORE. A simple section move would break those readers or leave stale authority claims. Any owner split must update the references and validator proof deliberately; an exact generated conditional projection may be a lower-churn alternative, but it needs independent proof that the phase still loads every applicable global invariant.
