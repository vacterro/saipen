# T-1373 REVIEW -- adversarial sweep over the citation boundary (2026-09-17, current bytes)

Each answer cites an existing control. No redesign was invented to answer one.

1. **Can a citation exist while its file is absent, and still read COMPLETE?**
   No. `cited_missing` becomes a `tier: cited` required omission
   (`saipen_evidence.py` evaluate, "cited evidence that never existed cannot be in
   ANY archive"), and the verdict drops to PROTOCOL_INCOMPLETE.
   Controls: AUDAPACK case35; reproduction case H; live census caught 4 real
   dangling proofs in __SAITULS (`review-fleet-citation-census.jsonl`).

2. **Can discovery truncate and still claim COMPLETE?**
   No. Every bound -- carrier count, bytes per carrier, bytes in total, distinct
   references -- sets `citation_truncated`, and the verdict branch turns any
   truncation into PROTOCOL_INCOMPLETE ("a citation discovery that stopped early
   cannot certify the rest"). Control: AUDAPACK case40, both halves
   (max_references=1 and max_carrier_bytes=16).

3. **Can an unreadable carrier silently disappear?**
   No. Unreadable directories, symlinked carriers, non-regular files, undecodable
   JSON and read errors all append to `unreadable_carriers`, which shares the
   same PROTOCOL_INCOMPLETE branch. An ABSENT carrier is not an error, by design:
   a file that does not exist cites nothing.

4. **Can an old contract bypass citation accounting?**
   No. A pre-SRC-054 contract gets `consumer_default` rules rather than none.
   Controls: AUDAPACK case32, case39; reproduction case G, which packs the
   pinned pre-SRC-054 contract as-is and still carries the cited proof with
   `rules=consumer_default`.

5. **Can a project with no evidence be falsely degraded?**
   No. The surface is conditional, never mandatory. Controls: AUDAPACK case36;
   reproduction case I (no evidence dir -> COMPLETE, omitted_required=[]); the
   census shows 11 live projects COMPLETE with zero citations.

6. **Can user prose synthesize fake required evidence?**
   PARTLY YES -- and this sweep proved it on SAIPEN itself. Source bodies and
   derived contracts are excluded as carriers (case37), so a handoff or a clause
   quoting a path stays inert. But LOG/BOARD/STATE and the coverage ledgers ARE
   carriers, and they legitimately hold prose. Writing SRC-054's R009 evidence in
   this very session spelled Problip's proof path in SAIPEN's coverage ledger,
   and SAIPEN's own snapshot flipped COMPLETE -> PROTOCOL_INCOMPLETE over a file
   that was never SAIPEN's evidence (census before: cited_missing empty; after:
   one entry). The sentence was reworded, the census re-run green, and the defect
   class filed as **T-1375** (reference grammar, T-1374's family). It is not a
   T-1373 hole: the failure direction is degrading, never a false COMPLETE.

7. **Can path or case ambiguity bind the wrong evidence?**
   No. `..`, `.`, absolute and drive-letter paths, and any path continuing a
   longer token are refused by the anchored pattern and `_citation_tail`
   (case37). Case-only differences resolve to the single on-disk entry, and a
   second candidate under the citation's own spelling is a collision the
   inventory refuses the whole pack over (`_on_disk_case`, case43, green).

8. **Can regeneration remove the evidence declaration again?**
   No. `evidence` is a canonical CONDITIONAL_DIRS entry, so every regeneration
   re-derives it, and `ensure()` reports `dropped_declarations` rather than
   silently narrowing. Controls: reproduction B (continue upgrades), D (recover
   restores, read-only status leaves the manifest byte-identical); the same
   oracle run against the pre-fix producer goes red on exactly B and D
   (`verify-problip-red-control-prefix-producer.txt`).

9. **Can the live Problip pack twice and keep the proof?**
   Yes. Reproduction C and E pack the fixture twice with the proof present and
   source/archive hashes equal, and the real fleet archive
   `_PROBLIP_16.09.26-T23-41-20.zip` produced by the fixed consumer carries the
   proof entry. Removing that single entry re-judges the archive
   PROTOCOL_INCOMPLETE (case J).
