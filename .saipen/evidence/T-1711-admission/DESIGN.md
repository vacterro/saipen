# Active regression execution: proposed contract

This is preparation while T-1712 owns the live seat and its source is frozen.
It does not create a second Work, change production bytes, or declare T-1711
implemented. The complete eighteen-clause SRC-212 mission remains open.

## Current consumer and supported route

The matched consumer is `_SAI_WEBSITE`, T-31 VERIFY. Its readback at E-356
has ordinary prose about red/green executions, not anchored identities for a
regression pair. The current classifier refuses it correctly. A diagnostic
RUN also claims a lifecycle failure and supersedes older ordinary greens.
The unavailable `run`/`declare` verbs and DONE-only `work reverify` are not
alternative supported admission routes. No foreign canonical file was edited.

The existing checkpoint route accepts properly anchored same-verifier pairs
in disposable active VERIFY fixtures. It proves identity arithmetic, not
engine execution. Confirmed gaps are contradictory identity tokens, combining
different producing attempts, and presenting arbitrary digests as executed
verification. Keep these facts distinct from the consumer's missing record
shape; do not claim that a green consumer execution is already admitted.

## Proposed compatible operation

Evaluate one documented `work regression T-N --file CONTRACT.json` operation.
Use the existing work effect owner, canonical operations journal, snapshot and
ownership checks, managed process tree, oracle comparison and Source gates.
Do not invent consumer-requested verbs or repurpose DONE re-verification.

The closed input describes command argv, supported summary format, oracle
paths, subject paths and the pre-fix bytes preserved under owned project
evidence. Current source supplies the post-fix bytes. No result, exit code,
verifier hash, receipt id or lifecycle verdict is accepted from the caller.
Unknown fields, overlapping oracle/subject paths, unowned/link/reparse paths,
missing material and unsupported verifier formats refuse before execution.

Run both sides in disposable immutable copies with the SAME oracle, argv,
runtime and environment. Require real collected-test summaries and expected
FAIL then PASS; missing summary, zero collected tests, launch failure, timeout,
oracle movement or unchanged subject cannot establish a pair. Retain measured
failed observations without granting lifecycle authority.

Bind project lineage, ticket, claim, exact current VERIFY boundary, producing
attempt (or explicit absence), Source identities, input manifests, command and
runtime identities, actual exit statuses, positive test counts and chronological
execution. Revalidate the original ownership/snapshot and subject/oracle bytes
after execution. Concurrent changes refuse without canonical writes.

Commit the measured pair and a typed immutable execution receipt through ONE
canonical operation, with its evidence in the existing journaled storage model.
Derive receipt authority from committed operation provenance and exact record
digest, never a user-supplied filename, hash or prose. Replay of the exact
subject/attempt/contract reuses the committed receipt without another pair.

Keep attested historical pairs accurately typed. A monotonic execution-bound
declaration can arm the stronger contract for explicitly upgraded active Work;
never retroactively label a historic checkpoint as execution or silently erase
an existing requirement. Final default/migration behavior must satisfy both
the forged-evidence rejection and previously valid-flow clauses, with explicit
compatibility tests. A new operation alone cannot prove the old route is safe.

## Readers and controls

Reject contradictory identities in the existing oracle parser; equal aliases
must remain compatible. Bind halves to the same real producing attempt through
the canonical attempt parser, including evidence recorded outside an attempt
after an earlier closed attempt. Preserve current VERIFY chronology: the latest
failure or a new VERIFY boundary invalidates an older approval. Both transition
and finish must derive the verdict from current authoritative history/receipt.

Before completion, prove actual executable red/green subjects and the native
CLI, absent pair, unrelated attempts, unknown verifier, forged/changed receipt,
stale and contradictory evidence, replay, byte-change races, foreign ownership,
read-only, write-free dry-run, unrequired-ticket compatibility, and historical
validity. Use one unchanged full oracle against the preserved old and final new
subjects; preliminary probes do not replace that pair. Run focused neighbors,
pinned Ruff, whitespace, native core and complete declared family. Independent
REVIEW repeats the oracle and inspects changes to the checks.

Report exact runtime paths/symbols, cause, supported CLI/API, measured controls,
compatibility boundaries and the consumer's next lawful operation. Deployment
and consumer repair remain separate; the operator prohibited publication.

## Measured preliminary prototype

`prototype-bindings.json` runs one unchanged eight-case oracle in a disposable
hash-checked copy: current code has five failures, the two-file identity/attempt
prototype passes all eight, and exact restored current bytes repeat the same
five failures. The positive controls preserve equal identity aliases, a pair
inside one real attempt and a legacy pair with no attempt. The negative controls
exercise contradictory identities, distinct real attempts, superseded-attempt
evidence and mixing an active attempt with absent-attempt evidence through real
canonical fixture operations. Production files did not change.

This is preliminary design evidence only. The genuine-execution operation,
receipt provenance and remaining SRC-212 controls are still unimplemented.
Its final expanded oracle will require its own full red/green pair.
