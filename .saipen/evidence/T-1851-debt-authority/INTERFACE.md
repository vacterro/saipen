# T-1851: exact native Decision B interface

This corrects acceptance of a missing/non-authorizing reference as operator
consent. It is a local implementation interface, not evidence of an actual
operator approval or host UI integration. No live project debt is registered,
reauthorized, rebound or edited by this Work.

`accept_legacy_debt.py --events E-N,... --preview --project-root ROOT` reads
the eligible historical event set and returns a capsule with project lineage,
check/version, canonical event IDs and exact line hashes. It writes nothing and
grants no authority. A native host presents this scope to the operator and fills
the affirmative statement and UTC approval-delivery expiry. The exact completed
JSON is the native `resolve-gate` event's body, captured through existing
`authority capture` as an authority-only Source. The host supplies the returned
original SRC reference to the public registrar. A generic model tool must not
self-issue this event, manufacture a witness or substitute a file/hash/env flag.

The existing broker authenticates native input and registers the actual worker.
`prepare_operator_debt` verifies the original Source, exact root/lineage,
event bytes, current worker and delivery scope; the owner reserves one exact
registration independently of its journal. `verify_operator_debt` confirms that
reservation and the canonical registration target. New methods use only the
authenticated production endpoint. There is no new service, key file, signer,
MFA flow, caller-selected production endpoint or direct native-proof flag.

Fresh missing, forged, model-authored, unrelated-action, wrong-scope, expired or
revoked approval cannot register debt. Reader verdicts are KNOWN/UNKNOWN; a
legacy integrity digest, Source ID or real model-written journal cannot turn
UNKNOWN into KNOWN. A known grant remains tied to its exact event bytes and
lineage across delivery expiry, task churn and a lineage-preserving move. It
grants no broader operation. Revocation or loss of the independent issuer/
reservation makes it UNKNOWN; existing kernel limitations are not hidden.

The broker retains the original bytes across a refused write. A canonical
PREPARED operation with no materialized targets still ABORTS under the unchanged
journal policy. The same approved effect may then receive a fresh numbered
attempt only after the owner independently observes that exact abort, absent
target and unchanged scope. The old journal remains intact. Written/VERIFIED
attempts recover only through their real artifact and semantic check. A revoked
written attempt remains a visible conflict and cannot be consumed as accepted.

For an old UNKNOWN record, preview includes the exact predecessor ID/hash. A
fresh independently witnessed decision may append a new acceptance explicitly
superseding that unchanged predecessor. Old record, Source, LOG and approval
claims remain immutable. Rebind retains original approval and exact event hashes;
it cannot authorize or widen an UNKNOWN acceptance. ALREADY_APPLIED also checks
the actual target; it does not claim a missing or stale-location record repaired.

Fixtures use the real broker, Source, registrar, validator and journal with
explicitly simulated native identity/process facts. Their green results do not
establish native FreeBuff/ZAICODE UI acceptance. Parent SRC-276's separate host,
historical E-371, archive, deduplication and full workflow outcomes remain due.
