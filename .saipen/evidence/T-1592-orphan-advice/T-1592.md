# T-1592 — the manifest's "Commit the file" advice must not stand unqualified

**Filed** 2026-10-02 from the T-1591 clone experiment (E-11310). **Built and
verified** on the same day.

## The defect

`tools/validate.py` refuses an untracked runtime file and prints:

> runtime manifest names a file git does not track: `<path>` — … Commit the file
> or drop the manifest entry

The first branch is unsafe whenever the file's **subject is also uncommitted**.
Following it trades a local FAIL for a red suite in every clone.

Measured on this repo, not hypothesised. Committing the two untracked `tools/`
tests made `python tools/validate.py --gate core` report zero manifest FAILs
here. `git archive HEAD`, extracted to a scratch tree, ran the same two modules
as:

```
Ran 5 tests — FAILED (failures=4, errors=1)
```

with two distinct causes:

| module | clone-side result | why |
|---|---|---|
| `tools/test_t1587_stale_closure_recovery.py` | `ImportError: cannot import name CLOSURE_METADATA_FIELDS from saipen_engine.board` | the constant exists only in this home's uncommitted `board.py` |
| `tools/test_improve_error_boundary.py` | 4 tests, 4 failures | HEAD's `main()` still leaks the raw `ImproveError` traceback — the exact defect T-3 exists to prevent |

Root shape: **210 modified files under `tools/` are ahead of HEAD**, so this
home runs a program no clone has.

That commit (`3e1631e8`) was reverted with `git reset --soft` — no worktree byte
touched, HEAD back to `7009c0be`, both files back to `??`.

## The repair

`validate.py` gains `_uncommitted_symbols(rel)`: it reads the untracked file,
extracts its `from X import a, b` statements, and for each named module asks
HEAD for the blob. A symbol HEAD does not carry is reported.

Two guards keep it quiet on ordinary files:

- **Only a module that exists in this home can be an orphan.** A stdlib or
  third-party name has no `tools/` path at all and is present in every clone.
  Without this the check fired on `pathlib`, `unittest`, `__future__` — caught on
  the first live run, not in a fixture.
- **The existing FAIL text is byte-identical.** It is a pinned baseline
  (`tools/validator_fail_sites.json`, site `0b3f14fa4247311c`, disposition
  `BASELINE`). The repair **adds** a `warn("manifest-untracked-orphan", …)` beside
  it instead of rewriting it. Verified: no fail-site drift after the change.

Cost is zero on a green home — the helper is only reached once a manifest file
is already known to be untracked.

## Verification

**Live, unmocked, on this tree** (`--gate core`, exit 1 from the two real
untracked files):

```
WARN [manifest-untracked-orphan]: untracked manifest file
tools/test_t1587_stale_closure_recovery.py imports runtime that HEAD does not
carry: saipen_engine.board.CLOSURE_METADATA_FIELDS -- do NOT commit it alone;
it will fail in every clone. Ship the runtime it depends on first
```

Exactly one warning, naming the precise symbol measured by hand in E-11310.

**`tools/test_t1592_manifest_orphan_advice.py`, 5 tests, OK.** The function is
exec'd from `validate.py`'s real source rather than imported — `validate.py` has
no `__main__` guard and ends in `sys.exit`, so it cannot be imported, and a copy
could drift. `git` is stubbed, so the tests pin the decision, not git.

| test | role |
|---|---|
| `test_a_symbol_absent_from_head_is_named` | the defect |
| `test_a_module_absent_from_head_entirely_is_named` | module form, not just symbol |
| `test_a_self_contained_test_reports_nothing` | positive control, incl. `pathlib` / `unittest` / `__future__` |
| `test_the_existing_fail_text_is_unchanged` | baseline preserved |
| `test_the_unsafe_branch_adds_a_warning_beside_the_fail` | the fix is wired in |

**Red control, scripted.** Replacing `return sorted(orphans)` with `return []`
(the pre-fix behaviour) and re-running:

```
FAILED (failures=2)
```

then restored and re-run: `OK`. The restore was confirmed byte-identical with
`git diff --no-index`. The two controls are not vacuous.

## Known limitation — stated, not papered over

The check is **import-level only**. `tools/test_improve_error_boundary.py` gets
no warning, yet it is equally unsafe to commit alone: its failure in a clone is
*behavioural* (HEAD's `main()` does not catch `ImproveError`), not an import
error. Import analysis cannot see that.

The second class — a file that reads its subject out of the source tree at
runtime — is also undetected. This ticket's own test file is an instance: it
execs `_uncommitted_symbols` out of `tools/validate.py`, which at HEAD does not
contain that function, so committing the test alone would ship an error. It is
therefore left untracked, and the gate correctly reports it as a third untracked
manifest file. Catching this class needs the tree materialised and executed,
which belongs to CI running the suite in a clone, not to a local gate.
