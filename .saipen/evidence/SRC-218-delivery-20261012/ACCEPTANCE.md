## T-1719 completion contract

T-1719 cannot close on documentation, a read-only model exercise, a script
editing a toy fixture, a cached prototype, or an advertised worker count.
Its deliverable is the admitted engineering workflow below. The independent
reviewer must check these outcomes against the original Source and preserved
amendments, not infer success from a generic PASS.

1. Record T-442's actual canonical DONE operation and T-443/T-444's admitted
   implementation scope before activating any engineering pool.
2. Prove one launch, two independent engineering agents, two eligible real
   audit generations, two isolated Git worktrees, durable worker identities
   and assignment generations, two actual source patches and two independently
   verified immutable handbacks. Record overlapping engineering execution
   intervals and distinguish models from mere subprocesses.
3. Integrate through the existing single Core path exactly once per proposal.
   Refuse stale and conflicting handbacks; revalidate the second handback
   against the source produced by accepting the first. Never hide a changed
   dependency behind a compatible-drift label.
4. Prove the admitted R5-R7 recovery milestone with a real terminated model
   session and a fresh session. Worker B recovers A's exact assignment,
   changes, completed verification and remaining work; it completes the same
   proposal, which Core accepts once.
5. Execute all eight negative controls in the mission: stale overwrite,
   expired lease, conflicting changes, deleted session, incomplete handoff
   falsely claiming VERIFIED, duplicate audit consumption, ledger divergence
   and unsafe ownership theft. Preserve the refusal evidence.
6. Retain exact-generation Source authority through assignment, proposal,
   verification, integration, Work closure and audit consume. An accepted
   patch does not itself make an audit terminal.
7. Demonstrate configurable pool size, resource-limited verification,
   inspection, safe worker reuse and sequential fallback under the admitted
   design. Use evidence-backed available host/model capabilities.
8. Benchmark 1, 2 and 4 only after their capability exists. Preserve accepted
   audits/day, verified integrated patches/day, waiting time, completion time,
   full-regression queue time, CPU/RAM, conflicts, stale refusals, restart lost
   work and human interventions. No invented throughput or reduced mandatory
   regression denominator.

The first useful milestone is step 2 plus safe sequential integration in
step 3, within T-444 after T-442 and T-443. General dynamic claims and recovery
remain T-445/T-446/T-448 follow-ons; T-451's long soak is not retroactively
required to demonstrate the first two workers. The full durable workflow
cannot claim T-1719 completion until its admitted recovery and negative
controls are demonstrated.

## Reuse and uncovered refinements

- T-443 owns the file-first contract, the invariant inventory, command naming,
  configured worker capabilities, bounded authority and the proposal binding.
- T-444 owns the two-worker engineering milestone, isolated worktrees, scoped
  source patches, durable handbacks and the single existing integrator.
- T-445 owns atomic logical-resource claims, assignment epochs, expansion and
  stale-worker fencing; T-444 may use Core's fixed preassignments before it.
- T-446 owns visible waits and deterministic deadlock resolution.
- T-447 owns durable command/intent identity and duplicate delivery behavior.
- T-448 owns progress inspection, checkpoint recovery, generation replacement,
  real worker loss and fresh-session continuation.
- T-449 owns the separate serialized release captain and stricter SHIP
  recovery. The first pool demonstration grants no publication authority.
- T-450 owns the evidence-based decision about canonical generated views.
  Keep authored files unless reproduced failures justify a reversible change.
- T-451 owns fixed-duration real-world soak and subsequent capacity evidence.

The backlog does not yet specify exact-generation audit dispatch bindings,
multi-provider capability selection, pool count configuration, resource budgets,
or the precise restart acceptance sequence. These are refinements for the
existing T-443/T-444/T-448/T-451 contracts, tracked by T-1719; they do not justify
duplicate implementation tickets. T-448 already owns loss and durable resume.

Reuse `ProducerPackage`, `classify_integration`, `derive_conflicts`,
`plan_integration` and `integrate_packages_core` from
`tools/saipen_engine/producer.py`. The existing package already binds base
HEAD/tree/model, role revision, scope, read/write hashes, epoch and immutable
identity; Core integrates under its writer lock with a journal. Its existing
producer roles are translation/wiki, not a proven engineering worker pool.
T-443 must specify the minimal compatible engineering assignment binding;
do not create a parallel incompatible package. Reuse audit inbox path+digest
generation, durable Source binding, allocator idempotency and exact-generation
delete gate from the existing audit/intake modules.

`future_gate/SAIPEN_FUTURE_WORKER_POOL.md` explicitly remains reference-only and
forbids automatic Work creation. The deferred multi-work document keeps one
live mutating lease per project for dispatcher V1. Separate isolated proposal
workers and one canonical integrator must respect that boundary; the current
mission does not authorize a multi-writer canonical ledger.
