TARGET A — SELECTED ACTIVE AUDIT MUST HAVE A REAL STOP PATH
============================================================

VERIFIED ROOT CAUSE

`audapack/services/audit_run_service.py::_actions_for()` currently exposes:

- WAITING / RETRYING -> CANCEL
- PREPARING / ATTACHING -> CANCEL
- STARTING / AUDITING / SAVING -> DETAILS only
- BLOCKED_POST_START / RECOVERY -> ABANDON

`audapack/ui_qt/dialogs/audit_runs_widget.py::_sync_actions()` enables the CANCEL button only when `"CANCEL"` exists in the run actions.

Therefore the supplied screenshot is consistent with the implementation: rows show `AUDIT 0/3`, which maps to AUDITING, and CANCEL is intentionally disabled.

This is not a dead click handler. It is a missing operator action.

The existing low-level safety model is correct and must remain:

`BrowserDispatcher.cancel_job()` is pre-START only because CANCELLED semantically asserts that no irreversible Core START occurred.

`BrowserDispatcher.abandon_job()` already accepts live post-START states, including START_PREPARED, STARTED, AUDITING and FINALIZING, and retires them as terminal FAILED with `operator_abandoned`.

Existing regression:
`tests/test_browser_dispatch.py::test_abandon_retires_a_live_auditing_dispatch_for_an_operator_stop`

IMPLEMENTATION CONTRACT

Add a first-class selected-run STOP action for live post-START work.

Recommended UX:

- pre-START selected run: button reads `CANCEL`
- live post-START STARTING/AUDITING run: the same primary stop surface reads `STOP`
- post-START BLOCKED run: retain the separate `FORCE UNBLOCK` recovery action
- terminal runs: no stop action
- do not mislabel a post-START stop as CANCELLED

Do not implement STOP by weakening `cancel_job()`.

STOP must use the existing honest post-START retirement path:

`AuditRunCoordinator.abandon(dispatch_id, "operator stopped active audit from Audit Runs panel")`

Prefer a distinct semantic action such as `"STOP"` in `AuditRunSnapshot.actions`, even if the same physical button is reused.

Required UI behavior:

- selected AUDITING row -> STOP enabled
- click -> explicit confirmation
- confirmation explains that the current Core may already have been sent
- successful stop -> run becomes terminal FAILED/operator_abandoned
- project lane becomes free
- the stopped dispatch is never re-leased
- no automatic fresh audit is started
- subsequent waves/continuations for that dispatch must not continue
- UI refreshes immediately and reports success visibly

A browser response already being generated at the instant of STOP may finish if there is no safe remote primitive for aborting the current ChatGPT response. The critical contract is that AUDAPACK retires ownership and schedules no further wave/retry. Do not fabricate stronger cancellation guarantees than the browser integration actually provides.

RACE FIX

`AuditRunCoordinator.abandon()` currently assumes every successful `/abandon` response means FAILED and updates the intent to FAILED unconditionally.

The Bridge endpoint returns the actual state. `abandon_job()` is idempotent and returns a terminal job unchanged.

Fix the completion race:

- if an audit reaches COMPLETE before STOP acquires the transition, do not rewrite a completed intent to FAILED
- honor the returned terminal state
- refresh and tell the operator that the run had already completed

TARGET B — INAUDIT SAVE MUST NEVER BE A SILENT NO-OP
============================================================

VERIFIED ROOT CAUSE

`audapack/ui_qt/dialogs/inaudit_widget.py::_action_state()` returns:

`EXISTING_LAYER_CLEAN` or `EXISTING_LAYER_DIRTY`

for every bound project that is not a managed draft or assignment, even when there is no physical active layer.

`_update_actions()` consequently enables Save for those states without requiring `_editor_path` or another valid persistence target.

`_on_save()` then does:

`p = self._editor_path`
`if p is None:`
`    return`

That is a literal silent no-op.

This creates an especially bad empty-project case:

- project selected
- zero INAUDIT layers
- editor remains usable
- Save is enabled
- operator types an internal audit
- `_dirty` becomes true
- Save remains enabled
- `_editor_path` is still None
- Save returns without saving or explaining anything

There is a second related state hole in `_load_editor()`: a failed layer read can leave `_editor_path=None`, while the high-level action state still looks like an ordinary existing layer.

IMPLEMENTATION CONTRACT

There must be no path where an enabled Save button silently returns.

Prefer the useful behavior rather than merely greying everything out:

If a project is selected, no physical layer/draft exists, the editor contains non-empty audit text, and the operator presses Save, interpret that explicit Save as creation of the first canonical internal audit.

Managed SAIPEN project:
- create/adopt a managed draft identity without destroying the text already typed
- use the existing canonical CaptureStore -> assign -> SAIPEN enqueue path
- preserve T-175 stable capture UUID/retry semantics

Unmanaged project:
- allocate the next legal INAUDIT layer through the existing canonical layer allocator
- bind the editor to it
- commit the exact typed text using the existing durable commit primitive
- refresh selection/action state

If the editor is empty and no layer/draft exists:
- perform no mutation
- show a visible reason such as `Nothing to save`
- never silently return

Add an explicit no-layer state to the action state machine rather than pretending a project with zero layers is an existing clean layer.

Every early refusal in `_on_save()` must set visible status.

On layer-read failure:
- do not present the editor as safely bound to an existing layer
- surface the load error
- do not let Save overwrite an unknown target from an empty/stale editor

Preserve:

- dirty-draft retention
- consumed-layer refusal
- changed-externally refusal
- managed assignment single-flight
- exact stable capture identity
- no recreation of consumed layers
- T-175 control isolation

CURRENT AUDAPACK FAILURE MODE

`audapack/source_inventory.py::build_git_inventory()` defines the primary Git source as:

tracked existing
UNION
untracked non-ignored

Ignored material is absent by construction.

An untracked nested Git worktree that Git does expose as `dir/` is intentionally represented as:

`reason = "untracked_git_directory"`

and is not traversed.

An ignored nested worktree such as ZAICODE `zcode/` is even less visible: outer Git never returns it in `ls-files --others --exclude-standard`.

Therefore AUDAPACK can produce a successful archive that contains workspace docs/SAIPEN evidence but no canonical application source.

Historical GitHub `_AUDAPACK_MANIFEST.json` demonstrates the symptom:
https://github.com/vacterro/zaicode/blob/master/_AUDAPACK_MANIFEST.json

That sample pack discovered 666 outer-workspace files, included 182 / about 2.7 MB, and its largest surfaces are SAIPEN evidence/docs. It does not represent the canonical `zaicode` app branch.

REFERENCE SIZE

Current GitHub `zaicode` branch inventory was measured from the recursive Git tree:

- 9,658 tracked files
- 143,740,016 tracked bytes total

Largest categories include approximately:

- `.ts`: 46.1 MB
- `.wav`: 38.1 MB
- `.gz`: 16.9 MB
- `.py`: 10.1 MB

So blindly archiving every tracked byte would restore source visibility but would also ship a lot of low-value audit weight.

The obvious ZAICODE-owned source/test spine identified from the repository's declared ownership paths is only about 4.87 MB across 627 files:

- UI ZAICODE source: ~2.74 MB
- shared ZAICODE contracts: ~0.27 MB
- services ZAICODE source: ~0.15 MB
- desktop ZAICODE main source: ~0.32 MB
- ZAICODE-named tests: ~1.34 MB
- ZAICODE scripts: ~0.06 MB

This proves there is plenty of room between today's nearly source-less package and a naive whole-checkout dump.

IMPLEMENTATION DIRECTION

Do not special-case the literal project name `_ZAICODE`.

Add a generic concept of a same-product nested Git component.

Automatic admission should be conservative:

1. Primary project root is a Git worktree.
2. Perform bounded nested-worktree discovery without recursively walking arbitrary ignored trees.
3. A direct child containing its own `.git` metadata is a candidate.
4. Resolve its Git root, branch, HEAD and origin through Git.
5. Normalize repository origin identity.
6. If nested origin equals primary origin, treat it as a canonical same-product component.
7. If origin differs, keep the existing safe omission behavior unless a future explicit policy authorizes it.

For ZAICODE this naturally admits:

`<project>/zcode`

because both roots are clones of `vacterro/zaicode`, while unrelated vendor sandboxes remain excluded.

Do not recursively archive `.git`, `.git/objects`, node_modules, dist, build, `.next*`, generated application bundles, private tool homes or runtime data.

IMPORTANT

Do not simply call the current primary `build_git_inventory()` recursively and merge everything unchanged.

Primary tracked files intentionally mean project truth and therefore bypass ordinary configured/fidelity exclusion.

A nested auxiliary component needs its own truthful compact classification so a tracked 38 MB WAV corpus or compressed vendor artifact does not become mandatory merely because it is committed upstream.

Preserve source/config/test truth while applying AUDAPACK's existing safety and fidelity vocabulary to auxiliary-component payload.

At minimum:

- source code: include
- project/package/build configuration: include
- tests: include
- relevant docs: include
- untracked non-ignored source edits: include
- hard secrets: exclude
- `.git/objects`: exclude
- node_modules/dist/build/runtime output: exclude
- compressed/binary build artifacts: exclude
- media: use existing fidelity/media policy rather than unconditional tracked inclusion

The archive must still be a truthful audit representation, not an arbitrary grep of filenames.

Do not hardcode only files containing `zaicode` in their name. Audits can require shared framework files and local modifications whose filename does not contain the product name.

SOURCE INVENTORY DESIGN

Prefer extending `SourceInventory` with component metadata while retaining `mode="git"` for backward compatibility.

Suggested component record:

- root-relative component path
- normalized origin identity
- branch
- HEAD
- dirty state
- discovered/included/excluded counts
- discovered/included/excluded bytes
- selection/fidelity mode

Archive members stay rooted under their actual project path, for example:

`zcode/packages/ui/src/zaicode/ZaicodeAuditPanel.tsx`

not flattened into a synthetic second root.

All existing frozen-stat/read-time revalidation invariants must apply to component files too.

If a canonical same-origin component is detected but cannot be inventoried reliably, fail the pack with a named component inventory error. Do not silently fall back to a package that claims success while omitting the application's source again.

If a different-origin nested repository is intentionally omitted, name that omission in the manifest.
